# Station 3 및 메인·NG 컨베이어 실장비 검증 계획

검토일: 2026-09-08. 현재 소스 기준의 검증 계획이며, 실장비 시험 완료 기록은 아니다.
이 문서를 작성하면서 실제 보드·모션·공압을 구동하거나 현장 설정을 변경하지 않았다.

## 턴온 당일 먼저 확인할 범위

이 문서는 전체 자동운전의 실장비 승인이 아니다. 아래 순서로 한 단계씩 확인한다.

1. 배포 버전·실장비 드라이버 선택·활성 유닛·DB 백업 확인.
2. 축을 움직이기 전 실제 DI 번호/극성과 도어·비상정지·서보 복구 확인.
3. 공압 단동 및 양쪽 끝단 DI 확인 → 캐리어 없는 상태로 필요한 헤드 상승.
4. 실제 `.mot`·홈 방향·펄스당 길이·축 범위를 확인하고 해당 유닛 Home.
5. 현장 티칭 및 단동 → 캐리어 하나로 정방향 동작 → Stop/재시작 → 반복 동작.

소프트웨어 검증에서 실제 배선, 기구 간섭, 관성 정지 거리나 모델의 현장 검출 성능은
확정하지 못한다. 기본 좌표나 Virtual 개발용 DB를 실장비의 검증된 티칭으로 간주하지 않는다.
처음부터 전체 유닛을 동시에 켜서 확인하지 않는다.

## 1. 확정된 입고 범위

- Station 3 검사부: 검사 카메라와 공용 X/Y 갠트리. Z축 없음.
- NG Transfer: 위 검사 X/Y를 함께 사용하는 캐리어 픽업.
- NG Shuttle: 캐리어를 아래 NG 컨베이어로 내리는 유닛.
- 메인 컨베이어 및 Station 1·2·3의 스토퍼·백업 플레이트·감지 센서.
- NG 컨베이어: 셔틀이 내려오는 3번 위치와 적재 위치 1·2.
- PCB Supply·Placement·볼트 체결 작업은 이번 자동 검증에서 제외한다.

공정 유닛을 끄는 것과 컨베이어의 해당 정차 위치를 제거하는 것은 다르다.
Station 1·2 공정 OFF여도 메인 컨베이어는 그 위치에서 캐리어를 받고, 안착시키고, 다음 위치로 보낸다.

최종 통합 검증에서 켤 설정은 아래 5개다. 실행 루프는 **4개**다.

| 설정 | 값 | 실행 책임 |
| --- | --- | --- |
| `MainConveyor` | ON | 메인 이송, 각 위치 스토퍼·플레이트, 전후단 SMEMA |
| `Inspection` | ON | Station 3 볼트 유무 검사 |
| `NgCarrierTransfer` | ON | 검사와 같은 `InspectionStation` 루프에서 NG 캐리어 이송 |
| `NgShuttle` | ON | NG 컨베이어로 하강·복귀 |
| `NgConveyor` | ON | 3 → 1/2 이동, 적재 및 작업자 배출 |
| `PcbSupply`, `PcbPlacement`, `BoltFastening`, 두 `BoltFeeder` | OFF | 이번 자동운전 제외 |

유닛 활성 여부는 현재 설정을 읽어 다음 운전에 적용한다. 다만 새로 켠 유닛의
하드웨어 초기화까지 완료됐다는 뜻은 아니다. 최초 턴온에서는 활성 유닛과 드라이버·매핑을
확정해 저장한 뒤 재시작하고, 초기화 결과를 확인한다. 운전 중 설정을 바꾸지 않는다.

## 2. 반영한 소프트웨어 조건과 설치 전제

### A. 검사 XY의 이동·홈 조건

`InspectionGantry`에서 NG 픽업 상승 DI를 확인한 뒤 XY 이동을 허용한다.
자동 검사·NG 이송뿐 아니라 Jog, Move To, 캐리어 스캔, 학습 포인트 촬영에도 같은 조건을 적용한다.
XY 이동 중 상승 피드백을 잃으면 알람과 공통 Stop으로 중지한다.

Home은 전체·검사 축 개별 명령 모두 다음 순서다.

1. 메인 컨베이어 입구·각 스테이션·출구, NG 픽업·셔틀, NG 컨베이어 P1/P2/P3의 캐리어 감지 DI가 모두 OFF여야 한다. 유닛 비활성 여부와 무관하다.
2. 작업자가 NG 픽업을 미리 올려 놓고, Up ON / Down OFF가 확인된 뒤 XY Home을 시작한다. Home은 그리퍼 Open이나 픽업 Up을 자동 출력하지 않는다.
3. 홈 중 캐리어가 감지되거나 필요한 실린더의 상승 확인이 풀리면 기존 취소 경로로 정지한다.

Home 명령으로 감지 중인 캐리어를 자동으로 떨어뜨리지 않는다.
NG 셔틀의 높이는 홈 허용 조건에서 제외한다. Station 3만 홈 잡을 때는 비활성
Placement·체결부 실린더 상승 DI를 요구하지 않는다. 이 유닛들도 홈을 잡는 경우에는
Placement Handler, Bolt Head 1/Head 2의 상승이 필요하다.
IPM 고정·승강 실린더는 헤드 전체의 상하 실린더가 아니므로 홈·XY 이동 조건에서 제외한다.
홈 전에도 정지·Manual·안전·알람 해제 상태라면 OUTPUTS에서 수동 조작할 수 있다.
운용 화면의 `RAISE CYLINDERS`를 누르면 홈 대상 유닛의 실린더만 한 번에 상승시키고
설정된 IO 타임아웃으로 상승 DI를 기다린다. 캐리어 DI는 모두 OFF여야 한다.
이 버튼은 축·그리퍼·진공·NG 셔틀을 움직이지 않으며, 완료 후 `HOME ALL`은 별도로 누른다.
STOP 시 기다림만 취소하고 공압 출력은 유지한다. 피드백 타임아웃은 해당 유닛 알람이다.
실린더를 수동 상승시키기 전 실제 기구 여유는 현장에서 확인한다.

근거: `InspectionGantry`, `MachineController.HomeAsync`,
`ManualHardwareViewModel`, `StationTeachingViewModel.Motion/Camera`.

### B. 비활성 작업은 컨베이어 실행과 무관하게 통과 가능

각 `StationWork`가 활성 설정을 받아, 비활성 공정은 별도의 완료 명령 없이 통과 가능하게 판단한다.
MainConveyor가 비활성 공정의 완료 상태를 대신 기록하던 코드는 제거했다.
`Inspection=OFF`, `NgCarrierTransfer=ON`, `MainConveyor=OFF`에서도 부팅 시 이미 들어온 DI로 판단한다.
실제 캐리어 존재·스토퍼·픽업·셔틀 조건은 그대로 DI에서 확인한다.

근거: `StationWork.Completed`, `InspectionStation.CurrentTransferState`, `NgCarrierMove.State`.

### C. 유닛 OFF는 IO 카드 미설치를 허용하는 설정이 아니다

Physical 제어는 AlphaMotion과 AJIN 초기화, 전체 `.mot` 로드, 전체 논리 DI/DO 맵 조회를 수행한다.
비활성 유닛의 축 설정 항목을 삭제하거나, 미설치 보드까지 자동으로 제외된다고 가정하지 않는다.
실제 설치 보드와 전체 매핑이 맞지 않으면 먼저 이 단계에서 막힌다.

또한 프로그램 초기화는 읽기 전용이 아니다. 활성 축에 Servo ON을 명령하고,
컨베이어·피더·슈팅·공급 SMEMA 등 정지 출력을 내린다.
Home/Start를 누르지 않았다는 것만으로 출력이 전혀 없다고 판단하면 안 된다.

근거: `PhysicalIoService.Initialize/CheckReady`, `AjinController.Initialize`,
`AjinMotionService.Initialize`, `MachineController.CheckHardwareAsync/StopRunOutputs`.

### D. 티칭값은 해당 설정 구분으로 DB에 저장

NG 픽업·셔틀 배치 Teach는 `NgCarrierTransferSettings`를 저장한다.
백업 플레이트 좌상단·우하단 핀 두 점은 `CarrierReferenceSettings`에 저장하며,
같은 좌표를 촬영 범위와 Station 2/3 좌표 기준에 함께 사용한다. 별도 스캔 양 끝 티칭은 없다.
각 프로젝트의 `GetTeachingPositions`가 좌표 읽기·반영과 저장할 설정 객체를 함께 정의한다.
티칭 화면은 해당 `TeachingPosition`을 사용하며 저장 대상을 별도로 분기하지 않는다.
현장에서는 Teach 후 재시작해 실제 티칭값이 유지되는지도 확인한다.
설정과 레시피의 저장소는 `Data/Machine.db`이며 유닛마다 별도 JSON 파일을 만드는 방식이 아니다.

## 3. 입고 전 준비할 것

- 실제 설치 IO 보드·모듈 목록, 최종 배선표, AJIN `.mot`, 보드·카메라 드라이버.
- `Data/Machine.db`의 실장비 설정·레시피·캐리어 영상, 별도 `TrainingData/BoltTraining.db`의 학습 데이터·모델. 배포/백업 범위는 `SETTINGS_STORAGE.md` 참조.
- 전후단 설비 또는 전장 담당자가 승인한 SMEMA 시험 장치. 후단에는 실제 수취 공간이 있어야 한다.
- 검증용 캐리어, 히트싱크 한쪽/양쪽 구성, 체결 완료품, 알려진 볼트 누락품.
- 기구·전장 담당자와 각 동작의 허용 영역, 초기 공압 상태, 안전한 시운전 속도 확인.

Virtual 개발 설정과 임의 좌표를 실장비 설정으로 복사하지 않는다.
`Virtual` 빌드는 장치 드라이버를 Virtual로 강제하므로 현장 제어용으로 쓰지 않는다.
현장용 일반 빌드에서 `Control=Physical`을 확인하고, 실제 영상 검증 단계에서는 카메라와 검사 알고리즘도 확인한다.
볼트 체결은 OFF이며 ADC 통신은 이번 검사·이송 검증의 선행 조건이 아니다.

현재 두 컨베이어 제어는 축 펄스 명령이 아니라 `Run / Reverse / NormalSpeed` DO다.
현물 드라이버가 이 신호를 어떻게 사용하는지, 실제 속도·정지 거리는 별도로 확인해야 한다.
UI 모션 속도나 타임아웃 값을 바꿔 컨베이어 정지 거리가 해결된다고 가정하지 않는다.

배선·수동 투입·걸림 제거는 현장 에너지 격리 절차로 진행한다. 프로그램 Stop은 전기·공압 격리를 대신하지 않는다.
안전장치 기능 시험은 전장 담당자의 승인된 절차로 시행하고, 인터록을 끄거나 DI를 우회하지 않는다.
이는 일반적인 안전 작업 원칙이며 이 설비의 안전 적합성 인증을 의미하지 않는다.
참고: [HSE 안전한 정비와 에너지 격리](https://www.hse.gov.uk/work-equipment-machinery/maintenance.htm).

## 4. 검증 순서와 통과 기준

한 단계가 통과한 후 다음 단계의 자동 유닛을 켠다. 처음부터 전체 Auto로 확인하지 않는다.

### 1단계 — 입력과 안전 회로

자동 유닛은 모두 OFF로 시작하되, 위 초기화 출력의 영향을 전장 담당자와 확인한 뒤 프로그램을 실행한다.
실제 센서·접점 하나를 변화시켰을 때 DI 창과 운용 화면에서 같은 의미로 나타나는지 대조한다.
IO 번호는 Settings의 매핑과 최종 배선표에서 확인한다. 이번 검토에서는 엑셀·실배선을 재대조하지 않았다.

| 구역 | 확인할 입력 |
| --- | --- |
| 공통 | E-stop 2개, 도어 6개, Auto/Manual, Reset, 서보 메인 접촉기, 저압 |
| 메인 | 전단 Available, 후단 Ready, 입구·출구 센서, 세 위치 캐리어·스토퍼 상하·플레이트 상하 |
| Station 3 | 히트싱크 1·2 감지 |
| NG Transfer | 픽업 상하, 그리퍼 열림/닫힘, 캐리어 감지 |
| NG Shuttle | 상하, 캐리어 감지 |
| NG 컨베이어 | 1·2·3 감지, 스토퍼 상하, 배출 요청·완료 버튼 |

현재 소프트웨어는 E-stop Pressed·Door Open·Air Pressure Low의 ON을 이상으로, Servo Main Contactor On의 ON을 정상으로 해석한다.
실배선 극성과 맞는지 확인해야 한다.

통과 기준: 다른 유닛의 DI가 대신 켜지지 않고, 신호 의미·정상 극성이 일치한다.
도어/비상정지 해제만으로 자동운전이 재개되지 않아야 한다.
사용자가 설명한 Auto 도어 개방 → RTEX 알람·서보 탈락, Manual 전환 또는 도어 닫힘 후 Reset 복구도 확인한다.
프로그램 Reset만으로 하드웨어 접촉기가 복구된다고 가정하지 않는다.

### 2단계 — 공압과 컨베이어 단동

무부하·허용된 공간에서 대상 하나씩 확인한다. DO 창은 저수준 정비 접근이며 자동 시퀀스의 간섭 확인을 대신하지 않는다.

- 각 스토퍼·플레이트, NG 픽업·그리퍼, 셔틀을 실제 동작과 DI로 대조한다.
- 지정 끝단 DI뿐 아니라 반대쪽 DI 해제도 확인한다. 두 DI가 모두 ON이거나 모두 OFF인 상태를 정상 끝단으로 취급하지 않는다.
- DO ON만 보고 완료로 판정하지 않는다. 기존 `TimeoutMilliseconds`와 현장 응답 시간을 대조한다.
- 메인/NG 모터 방향과 Stop 시 실제 정지, 이동 중 센서 체류 시간을 확인한다.

통과 기준: 실제 동작·끝단 피드백이 일치하고, 끼임·간섭·예상치 못한 다른 출력이 없다.
응답이 없으면 원인을 먼저 찾는다. 타임아웃만 무작정 늘리지 않는다.

### 3단계 — 검사 XY, 티칭, 카메라

검사 XY와 NG Transfer는 공용 축이며 Station 3 Z축은 없다. 2-A의 이동·홈 조건을 현장에서 대조한다.
`Inspection`·`NgCarrierTransfer`만 ON으로 저장·재시작하고 Auto Start는 하지 않는다.
모두 OFF인 상태를 유지하면 검사 축이 초기화되지 않으며, NG Transfer OFF이면 NG 티칭 항목도 표시되지 않는다.

- 최초에는 캐리어 없는 상태에서 NG 픽업 상승 및 기구 여유를 확인한다.
- 실제 축 번호, 펄스당 길이, 이동 범위, `.mot` 홈 방식·방향, 프로그램 홈 속도를 확인한다.
- 승인된 시운전 조건으로 Home 후 좌표 단위와 이동 방향, 정지·인포지션을 확인한다.
- NG 캐리어 픽업 XY, 셔틀 배치 XY는 현장에서 각각 티칭한다. 기본 `(0,0)`은 검증된 위치가 아니다.
- NG 티칭 후 재시작해 두 좌표가 그대로 복원되는지도 확인한다.
- 카메라 영상의 초점·노출·조명 채널과 mm/pixel을 확인한다.
- Live 카메라 중심에 백업 플레이트 좌상단·우하단 핀을 각각 맞춰 XY Teach → 캐리어 타일 촬영 → 이미지 배치/스케일 확인 → 이미지에서 볼트 클릭 티칭 순서다.
- 핀은 현재 위치 Teach로 등록하고, 등록된 핀은 Move To로 확인한다. 좌상단만 다시 티칭해도 우하단은 유지한다.
- Scan Carrier는 두 핀이 등록된 뒤 사용할 수 있으며 Live를 자동 종료한다. 두 핀 사이를 FOV와 Overlap에 맞춰 지그재그 촬영한다. 핀 바깥쪽 촬영 범위는 가장자리 프레임의 반 FOV까지이므로 필요한 캐리어 영역이 실제로 포함되는지 확인한다.
- 이미지 클릭은 볼트 위치만 저장하며 기준핀을 변경하지 않는다. 등록된 볼트는 Move To로 카메라 중심과 대조할 수 있다.
- 티칭 좌표와 실제 영상의 일치는 학습 화면의 티칭 포인트 촬영이나 4단계 검사 촬영으로 재확인한다.

통과 기준: 화면상 위치뿐 아니라 실제 카메라 중심과 티칭 위치가 일치한다.
검사만 켜면 체결용 Z·헤드 기준점은 필요 없지만, 검사 볼트 XY·두 기준핀은 필요하다.
자동 검사 시작 전 `BoltInspector.CheckReady`로 모델 준비를 확인한다. 모델이 없으면
검사 알람으로 시작하지 않는다. 시작 전 확인이 통과해도 실제 영상의 검출 품질은 별도 검증한다.

### 3-A단계 — 볼트 라벨링, 학습, 저장 모델 확인

- `Bolt Training`의 `Capture Taught Points`는 현재 안착된 캐리어에서 감지된 히트싱크의 티칭 포인트를 촬영한다. 원본 해상도 그대로 한 장씩 SQLite BLOB에 저장한다. 별도 이미지 파일·폴더는 사용하지 않으며, 프로그램의 샘플 선택 및 `Original` 탭에서 확인한다. 새 촬영 전에는 `Close Sample`로 현재 편집을 닫는다.
- `Station Teaching > Inspection Gantry > Inspection Recipe`에서 `Central ROI Size (px)`로 영상 중앙 정사각형의 한 변을 지정한다. ROI와 `Minimum Mask Ratio`는 제품 레시피에, 모델의 `Mask Threshold`는 학습 DB 설정에 저장한다. ROI 전체를 128×128로 리사이즈하며 학습·검사는 같은 전처리를 사용한다. 기본 ROI 128px은 광학적으로 확정한 값이 아니므로 실제 홈 크기와 위치 오차 여유를 보고 정한다. ROI 크기를 바꿔도 기존 모델을 사용하며 재학습을 요구하지 않는다. 기존 학습 샘플의 ROI·폴리곤은 유지한다. 실제 예측 마스크와 면적 기준은 별도로 확인한다.
- ROI마다 볼트 홈 둘레를 폴리곤 하나로 찍는다. 첫 점을 다시 클릭하거나 Enter로 닫고 `Save Mask & Next`로 꼭짓점을 DB에 저장한다. 우클릭·Backspace는 마지막 점을 취소하고, Esc는 현재 편집만 지운다. 실제 볼트가 없는 영상은 `No Bolt & Next`로 저장하며, 미라벨링과 구분한다. 마스크는 폴리곤에서 생성하며 따로 저장하지 않는다. 기존 샘플을 선택하면 저장된 폴리곤이 복원된다. 촬영·학습 취소 시 이미 DB에 저장된 데이터는 유지한다.
- 포함된 라벨링 샘플은 최소 5개이며, 학습·검증 양쪽에 볼트 있음·없음이 각각 있어야 한다. 이는 학습 실행 조건이지 현장 검출 성능을 보장하는 데이터 수량이 아니다.
- `Train`은 CPU 학습 후 검증 손실이 가장 낮은 모델 가중치를 DB에 저장한다. 별도 모델·체크포인트 파일은 만들지 않는다. 학습은 운용의 마스크·면적 판정 기준을 변경하지 않는다. 운용 검사에 이 모델을 쓰려면 `Inspection=TinyUnet`이어야 한다. `Virtual` 검사는 가상 판정기를 계속 사용한다.
- 시작값은 `Max Epochs=50`, `Advanced`의 `Batch Size=8`, `Learning Rate=0.001`, `Early Stop Patience=10`이다. Train을 누르면 설정을 DB에 저장한다. 검증 손실이 연속 10회 개선되지 않으면 최적 모델을 저장하고 정상 완료한다. `BEST EPOCH`는 검증 손실이 가장 낮았던 회차다. `Cancel`은 정상 완료가 아니라 이번 학습 취소이므로 기존 모델을 유지한다.
- `Inspect Selected Image`는 선택한 이미지의 화면상 ROI로 저장 모델을 실행한다. 미라벨·학습 제외 이미지도 가능하며 `Current` 판정·마스크·픽셀 비율과 `Recorded` 당시 판정을 구분한다. ROI·라벨·모델은 저장하지 않는다.
- `Review Validation Set`은 DB의 검증 샘플과 모델 가중치를 읽어 다시 실행한다. 재학습·기준값 재조정·축 이동은 하지 않는다. `Cancel` 또는 화면 이탈 시 읽기를 취소한다. `Exclude Sample`은 데이터 삭제 없이 학습에서 제외하고, `Use: Training / Validation`으로 라벨링한 샘플의 용도를 바꾼다.
- `Validation Images`는 데이터 검증 결과이며 실장비 재검사 결과가 아니다. 최종 확인은 아래 4단계에서 실제 체결품·누락품으로 수행한다.

### 4단계 — Station 3에 직접 안착시켜 검사

`Inspection=ON`, 메인·NG 자동 이송은 OFF로 시험한다.
직접 투입·안착은 안전하게 정지·격리한 상태와 승인된 작업 절차에서 수행한다.
검사 시작 조건은 캐리어 감지 + 플레이트 Up + 스토퍼 Down이다.
NG Transfer 자동을 꺼도 픽업 Up + NG 캐리어 미감지는 검사 진입에 필요하다.

- 히트싱크 1만 있음 / 2만 있음 / 둘 다 있음: 검사 시작 시 감지된 쪽의 볼트만 검사한다.
- 둘 다 없음: 촬영할 제품이 없으며 완료 후 NG로 분류한다.
- 모든 볼트 있음 / 알려진 한 볼트 누락: 실제 원본·마스크·판정을 대조한다.
- 검사 도중 Stop 후 Start: 현재 DI로 대상을 다시 정하고 미완료 검사를 처음부터 수행한다.

검사 도중 히트싱크 DI 변화만으로 작업을 취소하거나 완료·판정을 뒤집지 않는다.
캐리어 안착, NG 픽업 간섭 및 설비 안전 조건은 계속 적용한다.

통과 기준: 없는 쪽을 검사하지 않으며, 알려진 누락품을 OK로 통과시키지 않는다.
`Simulated` 결과는 이송 연동 확인에만 사용할 수 있고 실제 검사 품질 통과로 기록하지 않는다.
일부 샘플 통과와 생산 품질 승인도 구분한다.

### 5단계 — NG 배출 연동

검사와 NG Transfer·Shuttle·Conveyor를 켜고 메인은 OFF로 둔다.
4단계에서 판정한 NG 캐리어로 시작한다. 검사를 끈 NG 단독 시험도 2-B 조건으로 별도 확인한다.

1. Station 3 → NG Transfer 픽업 → 픽업 상승 → 셔틀 위 이동.
2. 상승해 있고 비어 있는 셔틀에 내려놓기 → 셔틀 캐리어 감지 → 픽업 상승.
3. 셔틀 하강 → NG 3번 감지 → 비어 있는 1번까지 이송 → 셔틀 복귀.
4. 1번 점유 시 다음 캐리어는 2번까지, 1·2번 점유 시 다음 캐리어는 3번에 적재.
5. 만재 시 추가 캐리어를 내려놓거나 밀어 넣지 않는다. Station 3의 NG는 기다린다.
6. 실제 배출 요청·완료 버튼으로 배출하고 남은 캐리어 정렬과 다음 수취를 확인한다.

통과 기준: 픽업이 내려와 있는 동안 셔틀이 하강하지 않고, 다음 수취 공간이 없으면 이송하지 않는다.
`AlarmCarrierCount`는 현재 램프·부저 기준이다. 설정 개수 도달 자체가 전체 자동 정지는 아니다.
적재 개수 표시와 3개 센서를 대조하고, 실제 만재에 따른 수취 차단은 별도로 확인한다.

### 6단계 — 메인 컨베이어

먼저 MainConveyor만 켜서 기계 이송을 확인하고, 이어 검사·NG 계통을 함께 켠다.
다른 공정 OFF는 해당 작업을 완료 처리하는 뜻이지 제품 품질을 보증하는 뜻은 아니다.
검사·NG Transfer가 모두 OFF인 단독 시험은 빈 캐리어도 후단으로 통과시킨다.
NG Transfer를 끈 상태의 통과는 품질 승인이나 NG 선별이 아니라 기계 이송 확인용이다.

- 전단 Available 및 수취 조건 확인 → Station 1 스토퍼 Up/플레이트 Down → Run.
- 입구 감지 후 전단 Ready 해제 → Station 1 캐리어 감지 시 정지 → 안착.
- Station 2가 비어 있을 때 1 → 2, Station 3가 비어 있고 수취 가능할 때 2 → 3.
- 이동 전에 도착 위치 스토퍼가 올라와 있어야 한다. 도착 감지 후 모터 정지 → 플레이트 Up → 스토퍼 Down.
- 보내고 받는 위치만 이송을 위해 플레이트를 내린다. 작업 중인 다른 캐리어는 플레이트 위에 남는다.
- 정상품은 후단 Ready OFF에서 대기하고, Ready ON 후 출구 센서 ON → OFF까지 확인하여 배출을 끝낸다.

통과 기준: 벨트에 내려와 움직이는 캐리어는 하나이고, 각 위치의 실제 도착 신호로 정지한다.
센서가 ON이어도 관성으로 밀리지 않는지는 실장비에서 확인한다. 소프트웨어 테스트로 정지 거리를 보증할 수 없다.
후단 수취 설비가 없으면 출구 밖 배출 시험은 보류한다.

### 드라이런의 제품 수량

2026-09-09 변경: 드라이런에서 **체결·풀기를 하지 않는다**. 대신 체결부의
티칭 포인트 이동은 모두 수행한다. 정상 생산과 별도 ADC 진단 시험은 변경하지 않는다.

준비 방식은 **Supply 그리퍼에 실제 PCB 한 장을 미리 물려두고 시작**하는 것으로 잡는다.
현재 PCB·고정 실린더·회전·축 피드백에서 다음 동작을 판단하며, 새 전단 SMEMA나
PCB 1·2 픽업부터 시작하지 않는다. 최초 준비 상태를 Stop/Run마다 강제로 만들지도 않는다.
그 PCB의 정방향·복귀 동작 중
다음 PCB를 추가로 집거나, 두 장을 모두 공급해야 한 사이클이 끝나는 조건을 적용하지 않는다.
이는 드라이런 조건이며 정상 생산의 PCB 1·2 공급 동작은 유지한다.
출발 위치를 PCB 1로 임의 고정하거나 한 장 픽업만으로 전단 캐리어를 배출하지 않는다.
현재 `Manual > Dry Run > PCB Return`에서 히트싱크 1/2를 선택하면
**앞 센서 → Station 1 안착 → 히트싱크 → 버퍼 → Supply** 복귀를 한 번 수행한다.
캐리어가 Station 2/3에 있으면 모든 스토퍼·플레이트를 내리고 앞 센서까지 역이송한 뒤,
Station 1 스토퍼를 올려 정방향으로 받고 플레이트를 올린다. 이미 Station 1에 있으면
불필요한 역이송 없이 안착부터 한다. Station 1 안착에서 컨베이어 동작은 정상 완료하며,
Station 2로 다시 넘어가지 않는다.
볼트가 체결되지 않은 PCB를 준비하고 Supply/Placement를 활성화해야 한다.
캐리어 안착이 아직 필요하면 Main Conveyor도 활성화하고 작업 헤드를 상승/안전 Z로 비운다.
Placement가 PCB를 유지한 채 인계 위치에 정지하면, Supply가 Clear Z에서 들어와
인계 Z로 상승하여 잡는다. Placement가 놓고 위로 빠진 뒤 Supply가 PCB를 들고 복귀한다.
Stop은 즉시 취소하며 Run은 실제 DI·축 위치와 진행 중인 복귀 방향으로 이어간다.
PCB 픽업을 시작한 뒤 Stop 중 히트싱크 선택을 바꿔도 진행 중인 회수 대상은 유지한다.
화면의 `Active`가 실제 대상이며, 새 선택은 현재 회수가 끝난 다음 새 회수에 적용한다.
앞 센서 또는 Station 1 안착 직후 Stop해도 남은 구간부터 이어간다. PCB 회수 중에는
컨베이어를 다시 시작하지 않는다. 역방향 끝은 **Supply가 PCB를 잡고 버퍼 밖으로 빠진 상태**다.
외부 공급 위치에 다시 놓거나 다음 정방향을 시작하지 않는다.
이 기능은 볼트 풀기나 NG 구간을 포함한 전체 설비의 연속 왕복은 아니다.
실장비에서는 낮은 속도로 Clear Z 진입·인계 상승·두 핸들러의 후퇴 간섭을 먼저 확인한다.

`PCB Round Trip`은 Supply에 미리 물린 PCB 한 장으로 **Supply → 선택한 히트싱크 → Supply**를
Stop까지 반복한다. 히트싱크가 둘 다 있어도 선택한 한쪽만 작업한다. 왕복 완료가 1 Cycle이다.
중간 Stop에서는 공압과 현재 방향·대상을 유지한다. 정지 중 대상 변경은 진행 중인 왕복을
마친 다음 사이클에 반영하며, 화면의 Active가 실제 진행 대상이다. 볼트는 체결하지 않는다.

### 6-A단계 — NG Transfer 실캐리어 왕복

센서 확정: P1은 DI-144, P2는 DI-145, P3는 셔틀에 달린 DI-142 한 개다.
사용자 확인에 따라 DI-146은 사용하지 않는다. 셔틀 승강 피드백 DI-140/141과
캐리어 감지는 별개이며, 셔틀을 올려도 캐리어 감지가 사라지지 않는다.

정방향 단동과 두 위치 티칭을 먼저 확인한 뒤 사용하는 수동 반복 시험이다.
`Manual > Dry Run > NG Transfer`는 **Station 3 ↔ 상승한 셔틀**만 반복한다.
메인/NG 컨베이어와 셔틀의 자동 루프, 검사, 다른 공정을 시작하지 않는다.

- Home은 캐리어를 넣기 전에 완료한다. `NgCarrierTransfer` 활성화와 Manual 조작 조건이 필요하다.
- Station 3 플레이트 Up / 스토퍼 Down, 셔틀 Up을 준비하고 한쪽에만 캐리어 하나를 둔다.
- Run은 실제 캐리어·그리퍼·상하 DI와 정지/인포지션 좌표로 다음 동작을 선택한다.
- 목적지가 비어 있어야 내려놓으며, 모든 XY 이동은 픽업 Up 이후다.
- 한쪽 이동 완료 때마다 Passes가 1 증가한다. 왕복 한 번은 2 passes다.
- Stop 또는 Manual 화면 이탈은 즉시 취소한다. 그리퍼를 풀거나 Home으로 되돌리지 않는다.
- 다시 Run하면 잡고 있는 중에는 기존 목적지를 유지하고, 놓여 있으면 실제 캐리어 감지 위치로 방향을 선택한다.

자동 NG 이송과 이 왕복 시험은 같은 `NgCarrierMove`의 상태/명령을 사용한다.
이 기능이 설비 전체의 제품 역이송·PCB 분리까지 묶은 반복을 의미하지는 않는다.

### 6-B단계 — 검사 위치 왕복

`Manual > Dry Run > Inspection Route`는 Station 3에 안착된 실제 캐리어를 움직이지 않고
카메라가 티칭된 위치를 왕복하며 촬영·판독하는 반복 시험이다. `Inspection` 활성화,
검사 XY Home, 플레이트 Up / 스토퍼 Down, NG 픽업 Up / 캐리어 미감지가 필요하다.

- Run 시 히트싱크 감지 DI가 있는 PCB만 선택한다. 각 PCB의 Data Matrix 중심,
  번호순 볼트 중심을 순방향으로 방문하고 마지막에서 역순으로 돌아온다.
- 같은 `BoltInspector`로 Data Matrix 판독과 볼트 유무 검사를 실제 수행한다.
  검사 드라이버가 Virtual이면 가상 검사이며, 실영상 품질 검증으로 간주하지 않는다.
- 현재 PCB·포인트·방향, 마지막 바코드/볼트 판정과 편도 Passes를 표시한다.
- 생산의 바코드·볼트 판정·작업 완료는 바꾸지 않는다. 캐리어 배출과 다른 자동 유닛도 시작하지 않는다.
- Stop, 화면 이탈, 안착/NG 픽업 조건 상실 시 취소·정지하며 공압은 유지한다.
  Run을 다시 누르면 현재 감지된 PCB로 경로를 구성하고 남은 포인트와 방향을 이어간다.
- 기준점·Data Matrix 티칭 누락, 모델 준비 실패, 바코드 판독 실패는 Inspection 알람으로 표시한다.
  볼트 누락 판정은 표시하고 다음 포인트로 진행한다.

이 시험은 촬상·검사·축의 반복 확인이다. 캐리어를 집거나 PCB를 분리하는 역공정은 아니다.

### 6-C단계 — 메인 컨베이어 실캐리어 왕복

`Manual > Dry Run > Main Conveyor`는 캐리어 하나로 **Station 1 → 2 → 3 → 앞 센서 → Station 1**을
반복한다. Station 3에서 설비 밖으로 배출하거나 전·후단 SMEMA를 교환하지 않는다.
공급·안착·체결·검사·NG 자동 루프는 시작하지 않는 컨베이어 단독 반복 시험이다.

- 캐리어를 넣기 전에 필요한 축을 Home하고 관련 헤드를 상승/안전 Z로 비운다.
  활성 유닛의 헤드 조건을 확인하며, 비활성 유닛도 작업자가 실제 간섭 없는 위치인지 확인한다.
- 캐리어 하나를 입구 센서 또는 Station 1/2/3에 놓는다. 첫 실행은 감지된 위치에서 이어간다.
  출구에 캐리어가 있거나 여러 위치에서 캐리어가 감지되면 시작하지 않는다.
- 전진은 목적지 스토퍼 Up / 플레이트 Down → 벨트 Run → 목적지 DI ON에서 Stop → 안착이다.
- Station 3 안착 후 모든 플레이트·스토퍼를 Down하고 역이송한다. 역방향 중간 위치에는
  받쳐 줄 스토퍼가 없으므로 **앞 센서 ON에서 정지**한 뒤 Station 1부터 다시 전진한다.
- Stop·화면 이탈은 즉시 취소하고 벨트를 끄며 공압은 유지한다. 활성 헤드 상승/안전 Z 조건이
  사라져도 취소한다. 재실행은 센서와 남은 목적지로 이어가며 센서 사이에서 멈췄다고 처음부터 리셋하지 않는다.
  프로그램 재시작으로 목적지 의도가 사라졌다면 감지 위치에서 캐리어를 확인하고 시작한다.
- Station 3 도달 및 앞 센서 도달마다 Passes가 1씩 늘어난다. 전 공정 결과를 보존하는 생산 모드는 아니다.
- IO 대기 시간은 기존 설정을 사용한다. 앞 센서 위치·실제 역방향·정지 관성·스토퍼/플레이트 완전 하강은
  저속 단동으로 먼저 검증해야 한다. Virtual 통과가 실기구 안전을 보증하지 않는다.

### 6-D단계 — NG 컨베이어·셔틀 실캐리어 왕복

`Manual > Dry Run > NG Conveyor Round Trip`은 **P1 ↔ 셔틀/P3**를 반복한다.
`NgConveyor`와 `NgShuttle`을 활성화하고 NG 픽업을 상승시킨 뒤 캐리어 한 개만 준비한다.
최초 시작은 P1·P2·P3 중 한 곳에서 감지돼야 한다. 자동 이송·배출 버튼 루프는 시작하지 않는다.

- 정방향: 셔틀 Down 확인 → 스토퍼 Up 확인 → Run → P1 ON에서 Stop → 셔틀 Up.
- 역방향: 셔틀 Down 확인 → 스토퍼 Down 확인 → Reverse Run → P3 ON에서 Stop → 셔틀 Up.
- P3는 셔틀에 붙은 센서이므로 상승 후에도 캐리어 감지가 유지된다.
- Stop은 벨트를 즉시 끄고 공압은 유지한다. 센서 사이에서 멈췄어도 현재 목적지로 이어간다.
- NG 픽업 Up 조건을 잃으면 시험을 취소한다. 한쪽 도착 및 셔틀 상승 완료마다 Passes가 증가한다.
- 저속으로 P1/P3 정지 위치와 관성, 셔틀 승강 간섭을 먼저 검증한다. 이 기능은 NG Transfer와
  메인 컨베이어를 함께 왕복시키거나, 캐리어를 작업자 쪽으로 배출하지 않는다.

### 6-E. 체결 포인트 왕복 — 체결·풀기 제외

`Manual > Dry Run > Bolt Route`를 선택한다. 체결부를 활성화하고 홈을 잡은 뒤
Station 2에 캐리어를 안착한다. 감지된 히트싱크의 포인트만 대상으로 한다.

- 헤드 2 PCB 전체 → 헤드 1 IPM 1차 전체 → 헤드 1 IPM 2차 전체 순서로 이동한다.
- 끝 포인트에서 역순으로 되돌아가며 Stop까지 왕복한다. 헤드별 기준점 변환은 생산과 같다.
- 각 체결 포인트에서 해당 헤드 실린더를 하강·상승한다. XY 이동은 두 헤드 상승 확인 후에만 한다.
- 픽업은 **픽업 XY → 헤드 1 하강 → 픽업 Z → Safe Z 복귀 → 헤드 1 상승**을 그대로 수행한다.
  진공을 출력하지 않고 피더·볼트 진공 감지는 기다리지 않는다. IPM 2차 경로에는 재픽업이 없다.
- 역방향에서도 경로에 포함된 픽업 위치를 방문해 같은 실린더·Z 왕복을 수행한다.
- 슈팅은 이스케이프 전후진부터 슈팅 에어·진공·공급 감지 대기까지 모두 건너뛴다.
- 체결 위치의 Z는 Safe Z이며, 체결 Z 이동을 추가하지 않는다. Z 왕복은 픽업 위치에서만 한다.
- 프리셋·ADC Start/Reverse 명령을 내보내지 않으며 생산 결과를 바꾸지 않는다.
- 중간 Stop 후 Run은 진행 중인 픽업/체결 위치와 실린더·Z 상태로 이어간다.
  캐리어 안착 신호가 사라지면 정지한다.

이는 독립된 체결부 경로 시험이며, 다른 드라이런과 연결된 전체 설비 반복은 아니다.

### 별도 — ADC 통신 및 체결 시험

Station 3 입고 시험의 선행 조건은 아니다. 체결기를 검증할 때 아래 항목을 적용한다.

- 두 컨트롤러의 실제 Slave ID, COM/통신 속도, 장비에 저장된 각 프리셋을 먼저 대조한다.
- 프로토콜 창 `Read Result`는 현재 Ready/Run/Alarm/Preset/Direction과 마지막 체결 결과를 구분한다.
  현재 상태는 3303~3309, 체결 이벤트 결과는 3200~3213 레지스터다.
- `Start Fastening`은 프로그램의 체결 시험 진입 조건과 Stop 처리를 사용한다.
  원시 4003=1 쓰기는 거부한다. 원시 Start를 정방향 체결로 몰래 바꾸지 않는다.
  4003=0 Stop은 유지한다.
- `Reverse (Hold)`는 선택한 Slave의 역회전 단동이다. Manual·축 준비·안전 조건을
  만족할 때만 누르는 동안 동작하며, 버튼 해제·영역 이탈·캡처 상실·STOP·창 닫기에서 취소한다.
  설정한 역회전 속도와 보호 제한은 ADC의 설정을 따른다. 축·헤드 실린더·피더·진공은 움직이지 않는다.
  실제 나사/비트 상태와 풀기 허용 여부를 확인하고 작업자가 지켜보며 사용한다.
  이 동작은 자동 풀기 완료를 반환하지 않는다. 화면의 `Stopped`도 풀기 성공 판정이 아니다.
- ADC 읽기/쓰기의 응답 시간 제한과 취소 시 진행 중인 Windows 직렬 IO를 중단하고
  정리한 뒤 공유 통신을 넘기도록 했다. 실제 카드/컨버터에서 통신 시간 초과와 Stop 응답은
  승인된 시험 조건으로 확인해야 한다. 통신선 단절 시 소프트웨어가 Stop 전달을 보장할 수는 없다.
- 매뉴얼의 4005=1은 풀기 방향이다. 그러나 해당 문서의 이벤트 결과에는 풀기 완료가
  정의되어 있지 않다. 역회전 시간 제한을 완료로 간주하지 않는다. 체결/풀기는 드라이런 범위에서 제외했다.
  `Model Complete`는 MA/MB와 다른 Model 프로그램 기능이다. Model의 Fastening 명령도
  프리셋 1~15만 명시되어 있어 MA/MB 완료로 대신 해석하지 않는다.

프로토콜 근거: `COM protocol for MDC and ADC September 2018.pdf`, Remote Control 및
Realtime Data 표. Windows 취소 처리 근거:
[.NET 10 SerialStream.Windows](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.IO.Ports/src/System/IO/Ports/SerialStream.Windows.cs).

### 7단계 — 대기, Stop, 재시작

- Station 3 검사 중 Station 1 → 2 이동 가능. Station 3 점유 중 2 → 3 진입 금지.
- 진행 중인 이송이 없고 다음 이송을 선택할 때, 뒤쪽 이송과 앞쪽 수취가 동시에 가능하면 뒤쪽 우선. 이미 시작한 수취를 중단하고 바꾸는 의미는 아니다.
- 후단 Ready 대기 중 정상품 유지, NG 적재 공간 대기 중 NG 캐리어 유지.
- 검사 이동 / 캐리어 이송 / NG 픽업·놓기 / 셔틀 하강 / NG 적재 각각에서 Stop.
- Stop 시 각 축과 Run 출력이 멈추고 공압 출력은 유지되는지 확인한다.
- 안전 조건 복구 후 명시적으로 Start했을 때 현재 DI·축 위치로 올바른 상태를 선택하는지 확인한다.
- 프로그램 종료·재시작은 Stop/Start와 별개로 확인한다. 재시작이 공정 결과를 복원한다는 가정은 하지 않는다.
- 캐리어가 이미 각 센서에 있는 상태로 부팅한 경우와 부팅 후 도착한 경우를 비교한다.
- 센서 사이에 멈춰 존재를 직접 알 수 없는 구간은 별도 기록한다. 감지되지 않은 위치를 기억한다고 가정하지 않는다.

안전장치·통신 이상은 우선 Virtual에서 검증하고, 현장에서는 승인된 무부하 시험 절차로만 재현한다.
가동 중 커넥터를 임의로 뽑거나 캐리어를 손으로 막아 고장을 만들지 않는다.

## 5. 기록과 다음 작업

각 시험은 `초기 DI/좌표 → 누른 명령 → 실제 동작/도착 DI → 판정`으로 기록한다.
실행 버전, 활성 유닛, `Data/Machine.db` 백업과 변경한 매핑·티칭값을 함께 남긴다.
설정 화면의 `Back Up Database`는 저장된 설정·레시피·캐리어 이미지를 포함한다.
`Restore and Exit`는 정상 종료 후 다음 시작에 복원하며, 운전 중인 객체를 교체하지 않는다.
학습 DB는 별도로 백업한다. 상세 분류와 이전 규칙은 `SETTINGS_STORAGE.md`를 참조한다.
속도·홈 방향·타임아웃의 현장 숫자는 기구·전장 확인 없이 이 문서에서 확정하지 않는다.

다음 단계는 실제 설치 보드·배선·`.mot`·공압 상태 확인 후 위 1단계부터 현장 검증하는 것이다.
Virtual 회귀 시험에는 전체 캐리어 DI에 따른 Home 차단, 하강/모순 DI에서 자동 상승하지 않음, 수동 상승 후 XY Home,
XY 이동 중 픽업 상승 피드백 상실, 비활성 검사 작업의 초기 DI 판단을 포함한다.
WPF 검증에서는 NG 티칭 저장·재로드와 이동 버튼 조건을 확인한다.
소프트웨어 시험은 실제 모션 정지 거리·전기 안전·기구 간섭·검사 품질 검증을 대신하지 않는다.

2026-09-06 수정 후 확인 결과:

- Release·Virtual 전체 빌드: 경고 0, 오류 0.
- Virtual 회귀 테스트: 81개 통과. 컨베이어 Run 준비 중 취소, 실린더 양쪽 DI 모순,
  Station 2 복구 시 기존 실측 NG·토크 보존, Stop/동작 종료 경합을 포함한다.
  Station 1~3 작업 중 히트싱크 DI 변경, Stop 후 대상 재선정,
  완료·NG 결과 보존과 검사 비활성 시 기존 배출 조건도 확인했다.
  복구 창에서 생략된 항목은 보존하고 명시적으로 체크 해제한 항목만 재작업 처리한다.
- 입고 구성의 부분 운전: Supply·Placement·체결·두 피더 OFF, 메인·검사·NG 계통 ON.
  검사 XY만 Home, 나머지 축 Servo OFF·미원점 상태에서 Start 가능하며,
  Station 1·2 경유 후 정상 후단 배출 및 볼트 누락 영상의 NG 적재를 확인했다.
  비활성 유닛의 ON 출력·ADC 프레임은 없고, 공통 정지용 OFF 출력은 유지한다.
- ADC 진단 창: 49개 확인 통과. 실제 ADC가 아닌 Virtual/시험 대역 사용.
