# Station 3 / NG / Repeat 현장 확인

기준: 2026-09-20 소스. 아래는 현재 구현을 확인하는 체크리스트이며,
실장비에서 검증 완료했다는 뜻은 아니다. 실제 배선·센서·간섭은 별도 확인한다.

## 메인 컨베이어

- Station 1·2·3의 캐리어 재실은 `Heat Sink 1 OR Heat Sink 2`다.
  두 입력이 모두 꺼지면 부재이며, 히트싱크 없는 캐리어는 취급하지 않는다.
  어느 하나가 계속 켜져 있으면 같은 캐리어의 작업 결과를 유지한다.
- 빈 스테이션의 백업 플레이트는 시작 준비에서 내린다. S1·S2의 캐리어는
  작업 지지를 유지하고, 작업 완료 후 해당 이송의 Release 단계에서 내린다.
  미검사 S3 캐리어는 가능한 다른 이송을 먼저 수행한 뒤 스토퍼 UP 확인 후 플레이트를 내려 검사한다.
  Station 3 히트싱크 입력이 모두 꺼져도 NG 집기 후 해제하지 않은 이송이 있으면 그 지지를 유지한다.
- 정방향 이송은 목적지 **히트싱크 2 감지 뒤** 설정된 시간만큼 더 구동해 물리적 간격을 이동한다.
  히트싱크 1만 감지됐을 때는 이 타이머를 시작하지 않는다.
  `CarrierStopDelaySeconds`는 센서 도착 제한 시간이 아니다.
  구동 전 플레이트 하강·스토퍼 상승 피드백이 필요하며, 실행 중 히트싱크 2가 지나갔어도
  1이 켜져 있으면 해당 구동 안에서 도착 이력을 유지한다.
  밀착 중 두 히트싱크 입력이 모두 꺼지면 정지하고 다음 작업으로 넘어가지 않는다.
  도착 후 S1·S2는 상승하지만, S3는 DOWN/스토퍼 UP/벨트 정지 상태에서 검사한다.
- 반입·이송·밀착·플레이트 상승·배출·역방향 복귀 중 STOP은 모터를 정지한다.
  새 START는 현재 센서와 축 피드백으로 동작하며 중단 이력에 따른 수동 확인·비움·RESET을 요구하지 않는다.
  실제 장치 알람이 발생한 경우에는 알람 원인을 해소하고 RESET한다.
  중단 뒤 들어온 도착 신호로 이전 캐리어의 작업 결과를 다른 캐리어에 붙이지 않는다.
- START 시 감지된 캐리어는 현재 착좌 피드백으로 동작한다.
- S3 도착 직후 S1 → S2나 전단 반입이 가능하면 S3를 올려 두고 그 이송부터 수행한다.
  S1 → S2 완료 후 전단 Available이 ON이면 S1 반입까지 마친 뒤 S3를 내려 검사한다.
  검사 요청 이후 새로 들어온 이송 요청은 검사·NG 픽업 위치 복귀 완료까지 기다린다.
- 검사 중에는 다른 캐리어의 벨트 이송도 정지한다. 검사 후 NG 픽업 대기 위치로 복귀한 뒤,
  OK + 후방 Ready이면 플레이트를 올리지 않고 바로 배출한다.
  그 외에는 OK 대기·NG 모두 플레이트를 올리고 스토퍼를 내려 앞쪽 물류를 허용한다.
  NG는 이 상승 지지 상태에서 픽업한다.
- 후방 배출은 Ready ON으로 시작한다. Ready OFF 또는 출구 센서 ON 후 첫 OFF부터
  설정된 여유 시간이 지나고 현재 OFF인 경우에 벨트를 정지한다.
  캐리어 구멍으로 잠깐 OFF됐다가 ON이면 계속 구동하며, 첫 OFF 타이머는 리셋하지 않는다.
  Settings의 `Exit Sensor Clear Delay (s)`는 기본 0.3초이며 스테이션 밀착 시간과 별도다.
- 백업 플레이트를 올리면 해당 스토퍼는 내린다.
- 비활성 스테이션은 작업 유닛의 모션/작업 출력을 실행하지 않는다.
  컨베이어 소유 백업 플레이트·스토퍼 처리는 남는다.
- 2→3은 Station 2 이송 준비와 Station 3 비어 있음 등을 확인한다.
  NG 픽업 상승은 입고 조건이 아니지만, 픽업이 이미 캐리어를 잡고 있으면 기다린다.
- Inspection이 비활성이면 Station 3은 NG로 처리한다.
  NG Transfer까지 비활성이면 기존 후방 SMEMA 배출 경로를 사용한다.

관련 코드: `MainConveyor.cs`, `ConveyorStation.cs`, `InspectionWork.cs`.
상태와 책임의 상세 기록: [MAIN_CONVEYOR_INSPECTION_SEQUENCE.md](MAIN_CONVEYOR_INSPECTION_SEQUENCE.md).
벨트가 안 돌면 DO 명령 여부와 실제 구동을 구분해서 확인한다.

## NG Transfer

- NG 캐리어 감지 ON은 주변 소재 감지이며, 집기 완료를 뜻하지 않는다.
  집기 위치 이동 → 하강 → 그리퍼 닫힘 확인을 수행한 이송만 운반을 이어간다.
  일반 자동은 감지 ON도 확인하며, 화면의 캐리어 표시는 감지 표시이지 그립 확인이 아니다.
  미완료 이송 이력은 STOP/RESET에서 유지한다. 해제 명령과 실제 그리퍼 Open 확인이
  함께 완료돼야 지운다. 이동 중 뜻하지 않게 Open이 들어와도 완료로 처리하지 않는다.
- 운반 XY 이동·목적지 하강 중 그리퍼 닫힘 또는 필요한 소재 감지가 사라지면 정지한다.
  그립이 불확실한 미완료 이송을 공중에서 재그립하지 않는다. 자동 해제에는 목적지 XY,
  픽업 하강, 받침 준비와 소재 감지가 필요하다. 빈 단독 Repeat만 소재 감지를 생략한다.
- Station 3에서 집으러 갈 때: **Carrier Pickup (S3)의 XY 동시 이동** 후 그 자리에서 집는다.
  티칭은 픽업 X/Y를 한 항목으로 함께 기록한다.
- 검사 종료 후와 빈 트랜스퍼의 일반 대기 위치도 NG 픽업 위치다.
- 셔틀에 놓거나 다시 집으러 갈 때도 티칭한 `Carrier Placement (Shuttle)`로 XY 동시 이동한다.
- 돌아와 Station 3에 놓은 뒤 빠질 때:
  **첫 번째 검사 FOV로 XY 동시 이동**한다.
- 첫 FOV가 없으면 빠지는 이동을 하지 않는다.
- Home은 위 일반 픽업 접근 순서와 별개다.

관련 코드: `Stations/IBTM.Inspection/NgCarrierTransfer.cs`.
이 유닛이 NG 실린더·그리퍼, 검사와 공유하는 XY 축, 자동 이송 상태를 함께 소유한다.
Supply는 `PcbSupplier`, Placement는 `PcbPlacer`, 체결기는 `BoltFasteningStation`에서
I/O·모션과 순서를 직접 실행한다. Repeat는 각 유닛의 별도 partial 소스 파일에 둔다.
`Work`는 메인 컨베이어와 공유하는 캐리어 결과·완료 소유권으로 유지한다.

## PCB 감지와 고정 판정

- Supply의 `Detected`는 픽업·인계 완료가 아니다. 티칭된 픽업 XYZ에서 그리퍼 닫힘과
  IPM 고정을 확인한 `Secured`만 인계 이동을 시작한다. 자동·Repeat 모두 적용한다.
- 일반 자동의 인계 이동 중에도 감지·그리퍼·IPM 고정이 풀리면 정지한다.
- Placement Repeat는 선택된 히트싱크에서 픽업을 수행하고 정해진 반환 경로를 따른다.
- Placement 수취 완료는 수취 이동 완료, 핸들러 상승, IPM 피드백, PCB 감지와 진공을
  함께 확인한다. 이 조건을 만족해야 Supply가 해제한다.
- Placement 수취 중에는 Supply 고정을 계속 확인하고, 수취 후 상승·Y 이탈·배치 이동
  중에는 Placement 고정을 확인한다. 고정 상실 시 다음 하강·해제를 진행하지 않는다.
- 압착 중 PCB 감지가 사라지거나 원래 캐리어가 바뀌면 조립 완료를 기록하지 않는다.
  이미 압착 완료한 PCB 위에서 감지가 남아 있어도 운반 중으로 판단하지 않으며,
  상승 중 취소되더라도 이미 기록한 작업 결과는 유지한다.
- 일부 고정만 남은 상태는 빈 핸들러로 취급하지 않는다. 확인된 지지 위치 밖에서
  START하면 임의의 이동·그립 해제를 하지 않고 원인 확인을 요구한다.
- HOME/START 준비에서 소재 감지 시 IPM 상승을 보류하는 보호 조건은 유지한다.
  이 조건은 주변 소재 보호이며 PCB를 잡았다는 판정이 아니다.

## Repeat

Repeat는 별도 가상 시퀀스가 아니라 기존 자동 유닛 동작에 반환 구간을 연결한다.
활성 유닛의 정해진 경로를 STOP 또는 알람까지 반복하며, 공통 사이클 횟수는 표시하지 않는다.
Teaching/Manual에서 사용하며, 시작 시 전체 캐리어 수를 합산해 실행을 차단하지 않는다.
소재가 필요한 유닛은 소재를 기다리고, 실제 이송·역송 시 지지·목적지·경로 조건을 확인한다.
NG 감지 ON만으로 보유 캐리어를 추가 계산하지 않는다. 집기 후 해제하지 않은 이송이 있으면
현재 그립·상승 피드백을 확인하고 셔틀 방향의 정방향 이송부터 이어간다.
NG Transfer 단독에서는 캐리어 없이도 S3 ↔ 셔틀 위치의 집기·왕복·해제를 반복한다.
꺼진 메인 경로의 S1·S2 소재는 개수에 포함하지 않는다.
START 허용 조건에서 Main Conveyor와 NG Transfer 활성화를 필수로 요구하지 않는다.
NG Conveyor가 활성화된 경우에는 NG Shuttle 활성화가 필요하다.
Supply 단독은 최초 PCB를 집은 뒤 인계 위치와 픽업 XY의 Rotation Z 사이를 고정을 유지한 채 왕복한다.
픽업 슬롯으로 하강하거나 PCB를 놓지 않는다. 상류 Available TEST는 최초 픽업·상승까지 필요하며,
이후 왕복에는 필요하지 않다. Main Conveyor나 NG 캐리어는 필요하지 않다.
메인과 Placement를 함께 사용할 때 최초 시작은 사용할 히트싱크에 PCB를 이미 안착시킨 캐리어 하나를 메인 입구(첫 번째)
센서에 올려놓고 START한다. 첫 Station 1 도착부터 기존 PCB를 집어 왕복하며,
PCB가 실려 있다는 이유로 Placement 왕복을 완료 처리하지 않는다.

| 마지막 활성 범위 | 반환 전 동작 |
| --- | --- |
| Placement까지 | S1 PCB 왕복·압착 완료 후 메인 역회전 |
| Bolt Fastening까지 | 피더 동작을 생략하고 S2 체결·결과 수집·헤드 상승 완료 후 메인 역회전 |
| Inspection까지 | S3 검사 완료·픽업 복귀·캐리어 상승 후 메인 역회전 |
| NG Transfer까지 | 셔틀 위치에서 내려가지만 그리퍼를 풀지 않고 다시 올라와 Station 3으로 반환 |
| NG Shuttle까지 | 셔틀에 놓고 셔틀 하강·상승 후 다시 집어 반환 |
| NG Conveyor까지 | NG 끝까지 보낸 뒤 셔틀로 역방향 반환하고 Station 3으로 반환 |

NG Transfer만 사용하는 Repeat에서는 비활성 셔틀의 Up/Down/캐리어 입력을 기다리지 않는다.
실제 셔틀에 내려놓는 경로는 셔틀 피드백을 확인한다.
픽업 자체의 상하·그리퍼 개폐 피드백과 Station 3 지지 상태는 여전히 필요하다.
Main Conveyor·Inspection·NG Shuttle·NG Conveyor가 모두 꺼진 NG Transfer 단독 Repeat만
소재 감지를 기다리지 않는다. 일반 자동과 연결된 Repeat의 소재 감지 조건은 유지한다.

체결기는 Repeat에서 피더 Enabled 설정과 관계없이 두 피더를 모두 OFF로 취급한다.
피더 자체 실행과 볼트 공급 대기를 생략한다. 픽업 이동·진공 출력은 유지하되 볼트 감지·진공 ON 확인은
생략하며, 슈팅 공급·이스케이프·발사는 수행하지 않는다. 두 헤드의 체결 모터 START·하강·결과 수집과
위치·실린더·진공 해제 확인은 유지한다. Enabled 설정값은 바꾸지 않으며 Repeat를 끄면 해당 설정을 따른다.

메인 반환은 입구 전용 센서에서 멈춘다. 다음 전진도 Station 1의 HS2 감지 후 설정 시간만큼
밀어 넣고 백업 플레이트로 캐리어를 올린다. Placement가 활성화되어 있으면 캐리어에 이미 있는
PCB를 집어 기존 인계 좌표까지 이동한 뒤 원래 히트싱크에 재안착·압착한다.
Supply도 활성화하면 인계 위치에서 Supply가 PCB를 고정한 뒤 Placement가 해제한다.
Supply는 PCB 고정을 유지하면서 픽업 XY의 Rotation Z까지 역이동한 뒤 정방향 인계한다.
원래 슬롯에 놓거나 다시 집지 않으므로 상류 지지와 Available TEST는 필요하지 않다.
두 히트싱크의 대상 PCB 왕복이 끝나야 다음 활성 공정으로 보낸다. 새 PCB를 추가 공급하지 않는다.
XY 이동·회전은 각 유닛의 이동 Z와 실린더 상승 조건을 유지한다.

Main Conveyor OFF에서는 Placement·체결·검사가 각자의 기존 캐리어 작업을 완료한 뒤 반복한다.
Placement와 체결 캐리어는 착좌 상태로 준비한다. NG Transfer OFF인 셔틀·NG 컨베이어는 자체 왕복한다.
독립 Supply와 NG 반복은 메인 역회전 때도 계속 동작하며, 설비 STOP 때 함께 정지한다.
STOP 후에는 진행 단계를 버리고 현재 피드백으로 판단한다. Supply가 잡고 있으면 정방향 인계,
Placement가 잡고 있으면 캐리어 쪽 정방향 배치를 이어간다. 인계 위치에서 양쪽이 함께 잡고 있으면
Placement 고정을 확인한 뒤 Supply를 해제하고 Placement가 상승한다. 원래 슬롯 복원은 요구하지 않는다.
미수집 체결 결과는 지우지 않는다. 체결된 PCB를 풀어 역인계하는 동작은 보류 상태다.

관련 코드: `IBTM/MachineController.Repeat.cs`,
각 유닛의 `*.Repeat.cs`. 기존 State를 재사용하며, MachineController는 연결된 유닛의
종료 대기·실행 취소·복귀 순서와 메인 역회전 경로 인터록을 조정한다.

## 짧은 현장 확인 순서

1. 실제 Settings의 축/IO 매핑과 센서 표시를 먼저 대조한다. 코드 기본값만 믿지 않는다.
2. S1·S2의 작업 지지가 유지되는지, S3는 START 당시 올라가 있어도 스토퍼를 올린 뒤 내려서
   검사하는지 확인한다. HS2 감지 후 추가 구동 종료 → S3 상승 → S1 → S2 → 전단 → S1 →
   S3 하강·검사 순서를 확인한다. 다른 이송이 없으면 상승 없이 검사해야 한다.
   검사 중 정지 유지 → NG 픽업 위치 복귀 → OK 즉시 배출 / OK 상승 대기 / NG 상승 집기의
   세 분기를 확인한다. S3 상승 대기 중 앞쪽 반입·S1 → S2 이송도 확인한다.
3. NG Transfer까지만 켜서 그리퍼를 유지한 왕복을 확인한다.
4. 셔틀과 NG Conveyor는 각각 활성화해 다음 구간을 확인한다.
5. 메인 이송/밀착 중 STOP 뒤 캐리어를 남겨둔 채 RESET 없이 새 START가 동작하는지 확인한다.
6. 첫 FOV가 있다면 복귀 후 빠지는 실제 경로를 저속으로 확인한다.

알람·대기를 만나면 현재 DI/DO, 축 상태, Enabled Units, Repeat 여부, 해당 시각 로그를 같이 남긴다.
조건을 추측해서 새 지연이나 재시도를 추가하지 않는다.

## 정지와 새 작업 시작 확인

- 압입 그리퍼 닫힘/압입 하강 중 STOP: 지지 플레이트와 소재 위치를 보존한 채
  중단을 완료로 기록하지 않고, 새 START가 현재 피드백으로 PCB 작업을 수행하는지 확인한다.
- 체결 결과 대기 중 STOP: 새 START는 확인된 결과를 먼저 수집한다. 결과가 없으면 같은 볼트·패스를 새 체결로 시도하며, 새 볼트를 공급하거나 다른 캐리어에 결과를 붙이지 않는다.
- 감지 직후 밀착 중 STOP과 플레이트 상승 중 STOP 모두 새 START가 현재 피드백으로 동작해야 한다.
  정지 자체로 지지대를 내리지 않으며, 수동 확인·RESET 차단이 생기지 않는지 확인한다.
- Station 2→3 정상 이송은 출발 시 선택한 작업 결과를 도착 캐리어에 전달한다.
  중단 뒤 들어오는 도착 신호에는 이전 결과를 자동 전달하지 않는다. 아직 전달하지 못한 결과는
  원래 출발 작업에 남고, 출발 스테이션에 들어온 다른 캐리어의 결과와 섞지 않는다.
- 자동/수동 운전과 STOP 정리가 겹칠 때 새 운전이 먼저 시작되지 않는지 확인한다.
- 비상정지·문·공압 입력이 들어오면 다른 축의 준비 상태 재조회보다 정지 요청이 앞선다.
  Virtual 검사는 이 소프트웨어 순서를 확인한다. 실제 안전 회로의 차단과 SDK 정지 응답 시간은
  배선·드라이버·실장비에서 확인해야 하며 이 검사로 검증한 것은 아니다.

로그의 `work=`는 앱 실행 중의 작업 추적 번호이며 실물 캐리어의 일련번호가 아니다.
정방향 스테이션 이송에서는 같은 번호로 결과를 따라가며, 캐리어 교체 시 새 번호가 생긴다.
유닛 단계·대상·`waitFor=`와 종료 시 마지막 단계를 먼저 보고 같은 시각 DI/DO를 대조한다.
