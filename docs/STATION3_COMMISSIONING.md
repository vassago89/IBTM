# 납품 전 공통 확인 / Station 3 / NG 현장 확인

현재 구현의 현장 확인 항목이다. 상세 순서와 책임은
[MAIN_CONVEYOR_INSPECTION_SEQUENCE.md](MAIN_CONVEYOR_INSPECTION_SEQUENCE.md)에 둔다.
Virtual 검증은 실제 배선·센서·기구 간섭 확인을 대신하지 않는다.

## 소프트웨어 사전 점검 기록

2026-10-03, 제어 코드 `7e236f01` 기준으로 `Virtual` 구성의 선별 회귀 검사 **42건 통과,
실패 0건, 건너뜀 0건**을 확인했다. 테스트 실행에 포함된 앱·의존 프로젝트 빌드도 성공했다.
대상은 물리/화면 RESET·중복 입력·STOP 취소·복구 실패, Auto 도어, 비상정지 우선 정지,
운영 확인 창 실린더, NG 비활성화·검사 재시작·DryRun 판정이다.
전체 `MachineFlow` 시뮬레이션, 납품용 Release 패키지 검증, 실장비 운전은 이번 점검에 포함하지 않았다.

추가 UI 점검은 1920×1080 / Windows 100% 기준으로 Virtual 피드백을 사용해 화면을 렌더링했다.
시작 검토의 플레이트 하강·위치 불명확·복구·캐리어 제거·대상 변경·실린더 대기,
수동 컨베이어 거부 사유, PCB 이력의 가체결 DryRun, 도어 개방 안내를 확인했다.
S2 재개 관련 선별 시험 13건과 플레이트/실린더 관련 선별 시험 5건은 각각 통과했다.
두 실행에는 중복 시험이 포함되므로 합산한 고유 시험 수로 표기하지 않는다.

후속 UI 점검에서는 Data Matrix 최대 임계값·검색 옵션 변경 후 이전 판정 초기화와 재검사 안내,
티칭 출력 피드백 미확인 시 버튼 비활성화, PCB 이미지 조회 중·빈 결과·조회 실패 표시를 확인했다.
이 점검은 임시 DB와 가상 서비스의 화면 렌더링으로 수행했으며 장비 초기화·출력 명령은 실행하지 않았다.
UI 수정 후 `Virtual` 앱 빌드는 오류·경고 0건, 해당 화면의 바인딩 경고도 0건이었다.

설정 8개 탭의 입력 오류 유지·저장 차단·운전 중 편집 제한을 추가 확인했다.
시작 검토의 I/O 단절·복구에서는 상세 실린더 표시가 미확인/실제 피드백으로 바뀌며,
S2 재개 안내는 미완료 자재가 있을 때만 표시된다. 플레이트 하강 시 재개 차단 안내는 유지된다.
OUTPUTS의 Normal Speed 버튼은 ON 고정, 안착 핸들러 회전 버튼은 OFF 고정으로 표시한다.
일반 출력의 ON/OFF 표시와 직접 출력 제어 조건은 유지했다.
추가 확인은 Virtual 서비스 또는 표시 전용 피드백으로 수행했고 실장비 앱은 실행하지 않았다.
최종 UI 변경 후 `Virtual` 앱 빌드는 오류·경고 0건, 확인 화면의 바인딩 경고는 0건이었다.

모션 진단·ADC 통신 화면도 피드백 누락을 확인했다. 축 상태 5개와 ADC 프리셋·알람은
빈칸 대신 `—`로 표시하며, 읽을 수 있는 축 좌표는 유지한다. ADC 오류 코드 탭의 확장 표시도 확인했다.
운전 도면의 S1·S2·S3 플레이트·스토퍼와 NG 셔틀 리프트는 I/O 단절 시 위치 미확인으로 표시한다.
상승·하강·센서 모순·통신 복구를 가상 입력으로 확인했고, 제어 명령과 인터록은 변경하지 않았다.

## 납품 대상과 실행 환경

- [ ] 납품 소스의 커밋, 실행 폴더, `IBTM.dll`의 SHA-256, 장비 번호, 확인 날짜와 담당자를 기록한다.
  현재 프로젝트에는 납품 버전 번호가 별도로 지정되어 있지 않으므로 파일 버전만으로 수정본을 구별하지 않는다.
- [ ] 장비 PC에서 64비트 프로세스와 .NET 10 Desktop Runtime을 확인한다.
  현재 기본 빌드는 런타임 설치가 필요한 WPF 앱이다. AJIN 제공 DLL과 AlphaMotion 호출은 x64다.
- [ ] AJIN 드라이버와 `AXL.dll`·`EzBasicAxl.dll`, AlphaMotion 드라이버와
  `tmcDApiAed_x64.dll`, Hik MVS 런타임을 확인한다. DLL 파일 복사와 장치 드라이버 설치는 별도다.
  2026-10-03 소스 점검 당시 `Hardware/IBTM.AlphaMotion/tmcDApiAed_x64.dll`은 없었다.
  프로젝트의 복사 설정만으로 파일이 만들어지지 않으므로 제조사 제공 파일 또는 장비 PC 설치 경로를 확인한다.
  Hik의 `MvCameraControl.Net.dll` 외에 네이티브 `MvCameraControl.dll`과 해당 런타임도 필요하다.
- [ ] 현재 장비의 축 번호·I/O 주소·극성, COM·카메라 연결값과 사용 유닛을 대조한다.
  양산에 사용할 비상정지·도어·공압 인터록 설정이 켜져 있는지 확인한다.
- [ ] 프로그램을 정상 종료한 뒤 기존 실행 폴더와 `Data/Machine.db`, 실제 설정된 결과·로그 폴더를 백업한다.
  실행 중인 SQLite DB의 본체 파일만 복사하거나 `-wal`·`-shm` 파일을 임의로 지우지 않는다.
  업데이트 때 장비의 DB를 개발용 DB로 덮어쓰지 않는다. 저장 위치는 [설정·레시피 저장](SETTINGS_STORAGE.md)을 따른다.
- [ ] 재실행 후 마지막 레시피, 티칭 좌표, I/O 설정, PCB 번호와 과거 결과가 유지되는지 확인한다.
  결과 폴더와 로그 폴더에 실제로 새 파일이 기록되는지도 확인한다.

## 공통 조작과 정지 확인

각 항목의 실제 결과·확인 시각·로그 위치를 남긴다. 아래 체크는 현장 확인을 마친 뒤 표시한다.

| 확인 | 조작 | 합격 기준 |
| --- | --- | --- |
| [ ] | 알람 원인을 해소한 뒤 화면 RESET과 물리 RESET 입력을 각각 사용 | 같은 복구 순서를 수행하며 정상 피드백 확인 후에만 알람이 해제된다. RESET만으로 자동운전이 시작되지 않는다. |
| [ ] | 리셋 중 물리 RESET을 다시 누르고 화면 RESET도 누름 | 추가 리셋이 실행되거나 예약되지 않는다. 리셋 중 STOP은 복구 동작을 취소한다. |
| [ ] | Auto 선택 상태에서 STOP 완료 후 각 도어 개방 | 도어 알람을 새로 발생시키지 않는다. 열린 상태의 START는 거절된다. 도어 입력은 닫힘 ON이다. |

| [ ] | 운영 확인 창의 실린더 동작 중 STOP 또는 창 닫기, 완료 센서 미감지 확인 | 후속 동작이 취소되고, 센서 미감지는 제한시간 후 오류로 표시된다. 명령 취소가 실제 실린더의 중간 정지를 보장하는 것은 아니므로 실물 위치도 확인한다. |

| [ ] | 피더 OFF 상태의 DryRun 결과 확인 | 해당 볼트의 운전 화면·종합 판정·저장 결과가 NG로 일치한다. Repeat 조작이나 자동 역송은 없다. |
| [ ] | 반입·밀착·체결·검사·NG 인계의 주요 지점에서 STOP 후 재시작 | 정지 출력과 축 피드백을 확인한다. 남은 PCB·볼트·미완료 인계는 필요한 확인 없이 지우거나 새 자재로 간주하지 않는다. |
| [ ] | 결과 저장 오류 안내와 재시도 절차 확인 | 저장 실패·대기 건수가 화면에 보인다. 미저장 결과는 메모리에 남으므로 재시도 성공과 대기 0건을 확인한 뒤 정상 종료한다. |

결과 저장 실패 때 현재 구현은 운전을 계속한다. 강제 종료·전원 차단으로 미저장 결과를 잃을 수 있으므로
이 경우 작업자가 생산을 정지하고 저장 경로를 복구하는 절차를 인계한다.

## 검사만 사용하거나 NG 컨베이어를 끈 경우

| 사용 유닛 | 현재 자동운전 동작 | 현장 확인 |
| --- | --- | --- |
| Inspection ON / Main Conveyor OFF / NG Conveyor OFF | S3 재실, 플레이트 DOWN, 스토퍼 UP, 벨트 정지 조건에서 검사하고 대기 위치로 복귀한다. 완료 캐리어는 S3에 남는다. | OK·NG 각각 검사 완료 후 재검사·자동 배출·NG 집기가 없는지 확인한다. S3의 검사 자세는 수동으로 준비한다. |
| Inspection ON / Main Conveyor ON / NG Conveyor OFF | OK는 후방 Ready에 따라 배출한다. NG는 S3에서 인계를 기다린다. | NG 컨베이어 OFF를 이유로 NG가 OK 경로로 우회 배출되지 않는지 확인한다. |
| Inspection OFF / Main Conveyor ON | 검사를 생략한 캐리어는 NG 취급하고 후방 SMEMA로 배출한다. | 검사 비활성 운전의 배출 경로를 작업자에게 인계한다. |

검사 완료나 인계 대기는 전체 자동운전의 STOP을 뜻하지 않는다.
자재를 수동으로 처리하거나 유닛 설정을 바꾸기 전에는 STOP 완료와 수동 모드를 확인한다.

## 메인 컨베이어

- S1·S2·S3 재실은 `Heat Sink 1 OR Heat Sink 2`다. 두 입력이 모두 꺼지면 부재이며,
  정방향 이송 중의 순간적인 OFF만으로 캐리어 작업을 바꾸지 않는다.
- 정방향 이송은 목적지 **HS2 감지 뒤** `CarrierStopDelaySeconds`만큼 더 구동한다.
  HS1만으로 타이머를 시작하지 않는다. 밀착 중 입력이 잠깐 OFF돼도 정지하거나 시간을 다시 재지 않는다.
  밀착 시간이 끝나도 두 입력이 모두 OFF이면 정지하고 오류를 낸다. STOP과 지지 위치 인터록은 즉시 적용한다.
- S1·S2는 밀착 후 백업 플레이트 상승·스토퍼 하강으로 착좌한다.
  S3는 DOWN/스토퍼 UP/벨트 정지에서 검사한다.
- S3 도착 후 다른 반입·이송이 가능하면 검사 갠트리가 **S3 픽업 위치로 이동한 뒤**
  S3 플레이트를 올리고 스토퍼를 내린다. 다른 이송 종료 후 S3를 내려 검사를 요청한다.
  이미 S3가 상승해 있는 경우에도 현재 지지 상태에서 이 순서를 판단한다.
- 검사 요청 이후 새 벨트 이송은 검사·전용 대기 위치 복귀 완료까지 기다린다.
  OK + 후방 Ready이면 불필요한 상승 없이 바로 배출한다.
  OK 후방 대기·NG는 픽업 위치 이동 후 상승하여 앞쪽 물류를 허용한다.
- 후방 배출은 Ready ON으로 시작하고 **Ready OFF → `RearSmemaOffDelaySeconds` → 정지**한다.
  출구 센서는 사용하지 않는다. 추가 시간 기본값은 0.3초이며 밀착 시간과 별도다.
  Ready가 다시 ON되어도 추가 시간을 다시 시작하지 않는다.
  지지 해제 중 Ready가 먼저 OFF되면 벨트를 새로 켜지 않는다.
- STOP은 반입·이송·밀착·배출 중에도 모터를 정지한다.
  새 START는 현재 피드백으로 다음 동작을 고르며 이전 배출 타이머를 이어 쓰지 않는다.
- S2 → S3 결과는 도착·밀착 완료 뒤 벨트 OFF 통지 전에 전달한다.
  중단 뒤 들어온 센서만으로 이전 결과를 다른 캐리어에 전달하지 않는다.
- Inspection과 NG Transfer의 Enabled는 하나다. 꺼져 있으면 검사 NG로 취급하며
  후방 SMEMA로 배출한다. 비활성 갠트리의 대기 위치 이동은 요구하지 않는다.

관련 코드: `MainConveyor.cs`, `ConveyorStation.cs`, `InspectionStation.cs`.

## 검사와 NG 인계

- `WaitingPosition`과 `CarrierPickupPosition`은 별도 좌표다. 검사 후에는 대기 위치로 복귀한다.
  S3 상승·집기는 픽업 위치에서 수행한다. 셔틀 좌표는 `ShuttlePlacePosition`이다.
- 각 위치로 이동할 때 X/Y는 동시에 움직인다. 티칭 Move To도 같은 이동 경로를 사용한다.
- 검사는 PCB 1의 Data Matrix·볼트 번호순 검사를 마친 뒤 PCB 2로 넘어간다.
  판독 실패·볼트 검사 NG는 결과로 남기고 다음 포인트를 검사한다.
  ROI 미티칭과 장치·이동 실패는 단순 검사 NG와 구분한다.
- `NgCarrierDetected`는 화면 표시 전용이다. 집기·이송·해제 판단에 사용하지 않는다.
  S3 또는 셔틀의 소재 감지와 지지, 픽업 상하, 그리퍼 개폐 피드백은 확인한다.
- 집기를 시작한 미완료 인계는 STOP/RESET에도 남는다. 그리퍼 해제 명령과 Open 확인이
  완료돼야 해제한다. 이동 중 뜻하지 않게 Open이 들어와도 인계 완료로 처리하지 않는다.
- 운반·목적지 하강 중 그리퍼 닫힘을 잃으면 정지한다. 지지 없는 위치에서 임의로 재그립하지 않는다.
- 일반 자동은 셔틀에 놓고 그리퍼 해제·픽업 상승 후 **셔틀 DOWN을 확인해야** 대기 위치로 돌아간다.
  이 대기는 STOP 후에도 남으며 수동 XY 이동에도 적용한다.
- 셔틀 수취 조건이 풀리면 검사 유닛이 변경 통지를 받아 다시 판단하는지 확인한다.
  그리퍼 해제·픽업 상승 전에는 셔틀이 내려가면 안 된다.

검사·NG 트랜스퍼는 `InspectionStation`, 셔틀·NG 벨트는 `NgCarrierConveyor`가 각각 한 루프로 처리한다.

## 짧은 확인 순서

1. 저장된 축·I/O 매핑, 대기·픽업·셔틀 티칭 좌표와 실제 피드백을 대조한다.
2. S3 도착 → 다른 이송이 있으면 픽업 위치 이동·상승 → 앞쪽 이송 → S3 하강·검사 순서를 확인한다.
3. 검사 → 전용 대기 위치 복귀 → OK 즉시 배출 / OK 상승 대기 / NG 상승 집기를 확인한다.
4. 일반 NG 인계 후 셔틀 DOWN까지 XY가 기다리는지 확인한다.
5. START를 누를 때 Supply·Placement의 PCB, 헤드 볼트 또는 미완료 캐리어가 남으면 구동 전 거절되는지 확인한다.
   들었다 놓아도 이력은 유지하며, 제거 후 시작 검토 창의 **다시 확인**을 누른다. 완료 캐리어와 NG 셔틀은 배출 흐름을 유지한다.
6. S1 밀착과 후방 Ready OFF 추가 운전을 각각 확인한다.

알람·대기가 생기면 같은 시각의 `Step`, `target`, `waitFor`, DI/DO, 축 피드백을 대조한다.
로그의 `work=`는 앱의 결과 추적용 Job 번호이며 실물 캐리어 일련번호가 아니다.
