# 전체 소스 검토 — 2026-09-14

## 판단

주요 생산 경로를 설비 동작·정지·재개·결과 귀속 기준으로 검토했다. 유닛별 시퀀스, 장치 호출, 공통 I/O·모션 경계는 현재 구성을 유지해도 된다. 이번에 확인된 우선 수정 대상은 **완료 신호를 과거 이력으로 받아들이는 경로**와 **볼트 티칭이 없는 소재의 작업 완료 처리**였다. 둘 다 수정 전 가상 테스트로 재현하고 수정했다.

전체 파일의 무결성이나 실장비 적합성을 보증하는 검토는 아니다. 제조사 SDK 원본을 전부 재검증하지 않았고 실장비 동작·통신·UI 조작은 수행하지 않았다.

## 수정 1 — 실린더 완료 신호의 현재 상태 확인

위치: `Shared/IBTM.Device/IIoService.cs`, `WaitForInputsAsync`.

수정 전에는 기대 센서 ON·반대 센서 OFF가 한 번 확인되면 Task가 완료됐다. 시퀀스가 이어지기 전에 기대 센서가 다시 OFF가 되거나 반대 센서도 ON이 되어도 성공을 반환했다. 두 경우를 실행 순서를 고정한 테스트에서 재현했다.

기존 공통 이벤트 대기를 사용해, 액추에이터 완료는 반환 직전 센서 쌍을 다시 확인한다. 조건이 사라졌으면 처음 정한 제한 시간 내에서 계속 기다리며 출력 명령을 재전송하지 않는다. 볼트 통과 등의 단일 입력 대기는 짧은 펄스를 계속 기억한다. 별도 감시 루프나 안정화 시간 설정은 추가하지 않았다.

## 수정 2 — 볼트 티칭 누락을 작업 완료로 처리하지 않음

위치:

- `IBTM/MachineController.Automatic.cs`, `TeachingReady`.
- `Stations/IBTM.BoltFastening/BoltFasteningStation.cs`, `RunCarrierAsync`.
- `Stations/IBTM.Inspection/InspectionStation.cs`, `ExecuteInspectionAsync`.

수정 전에는 HS1 볼트만 등록하고 HS2가 들어오면 HS2의 작업 목록이 비어 있어 체결·검사 모두 완료됐다. 실제 자동 시작 경로를 사용하는 가상 테스트에서 두 유닛의 `work.Completed == true`를 확인했다. 검사만 사용하는 경우에는 Data Matrix FOV만 등록해도 볼트 목록이 없는 레시피를 준비 완료로 판단했다.

이제 활성 체결·검사 유닛은 최소 한 개의 볼트 티칭을 요구한다. 소재가 안착하면 이번 작업 대상 히트싱크 각각에 볼트가 등록되어 있는지 확인하고, 없으면 대상 이름을 포함한 알람으로 정지한다. 완료나 OK 결과를 만들지 않는다. 해당 유닛을 비활성화한 이송 운전에는 이 조건을 적용하지 않는다.

## 검토 범위와 유지한 동작

| 범위 | 대조한 주요 내용 |
| --- | --- |
| 자동 시작·정지·복구·종료 | 상위 명령 소유권, 자식 작업 정리 대기, 각 장치 STOP 시도, 원래 오류 보존, 정리 후 감시 종료 |
| I/O·축 감시와 드라이버 | 입력 스캔 실패 시 무효화, 출력 읽기 오류, 현재 SDK 피드백, 축 정지·InPosition 확인, 화면 취득과 명령 전 확인의 구분 |
| Supply → Placement | 잡은 상태로 직접 인계, Placement PCB 감지·진공·그리퍼 확인 후 Supply 해제, 이탈 대기, 이송 높이·해제 순서 |
| Main Conveyor | HS1 OR HS2 재실, HS1 감지 후 추가 밀기 시간, STOP 후 밀기 재개, 소재 상실, 플레이트 지지, 작업 결과 인계 |
| 볼트 피더·체결 | 볼트 통과 입력, 헤드·피더 준비, 중단 결과의 캐리어·볼트·공정 귀속, 프리셋·방향과 STOP 확인 |
| 검사·티칭 | 밝은 픽셀 비율, 볼트별 임계값·합격 비율, 대상과 FOV·ROI 연결, 줄자 보정 시 양쪽 볼트 좌표 계산, 촬영 XY 보존 |
| NG·Repeat | 그리퍼·리프트·셔틀 지지, 미완료 목적지 보존, 센서 사이 정지 시 위치 미확정 처리, 전진 작업 정리 후 복귀 |
| 저장·UI 구조 | 레시피·이미지 저장 트랜잭션, 저장/로드 실패 표시, 화면 전환 시 취소, XAML 바인딩 원본과 표시 갱신 |

폐기한 캐리어 센서는 생산 경로에서 더 이상 사용하지 않는다. 열거형의 옛 이름은 저장 설정 호환을 위해 남아 있고, 기존 설정의 폐기 매핑은 구성 시 제거한다. 검사 학습 프로젝트와 Clear Images의 생산 코드 참조도 남아 있지 않다.

`BufferStage` 등의 이름은 남아 있지만 현재 역할은 두 핸들러의 인계·간섭 구역 확인이다. 물리 버퍼의 내려놓기 동작을 다시 추가할 이유는 없다. 이름 일괄 변경이나 유닛 시퀀스의 추가 공통화는 이번 결함 해결에 필요하지 않아 수행하지 않았다.

## 검증

Virtual 구성의 직접 관련 테스트 **20개 통과**. 테스트가 의존 프로젝트를 빌드했으며 전체 솔루션 추가 빌드와 `Category=MachineFlow` 전체 실행은 하지 않았다.

- I/O 수정 관련 13개: 현재 실린더 피드백 2, 통과 펄스 1, 직접 인계 1, 인계 중 진공 상실 1, 스테이션 실린더 3, 티칭 출력 취소 1, NG 액추에이터 1, 체결 헤드 피드백 2, 유효 입력 스캔 1.
- 티칭 누락 관련 7개: 빈 검사 목록 준비 차단 1, 재실 히트싱크 미등록 2, Data Matrix 실패·복구·정상 검사 1, 체결 결과 귀속·복구 3.
- 변경 파일 공백 검사 통과.

추가 현장 확인은 실제 ADC 모델·펌웨어의 상태 갱신, 장착된 카메라와 축의 방향·해상도 보정, 직접 인계의 지지·이탈 동작에 남아 있다. 소스와 가상 검증만으로 해당 물리 조건을 확정하지 않았다.
