# 스테이션 실행 구조

큰 실행 단계를 선택하고, 단계 안의 장치 동작은 `await`로 순서대로 실행한다.
센서가 변할 때마다 실행 중인 단계를 다시 선택하지 않는다. 피드백은 동작 완료 확인과
인터록에 계속 사용하며, 해당 단계가 끝난 뒤 다음 동작을 결정한다.

## 세 가지 정보

| 정보 | 역할 | 수명 |
| --- | --- | --- |
| `AutoUnit.Step` | 현재 실행·대기 단계. 화면 표시와 실행 경계 확인 | 현재 Run 동안, 종료 시 활성 단계 없음 |
| I/O·Motion 피드백 | 실제 위치·구동·그립·준비 조건 | 장치에서 관측한 현재 값 |
| 작업·인계 정보 | 대상 PCB, 결과 소유권, 미완료 인계 | 각 작업/인계가 끝날 때까지 |

`Step`만으로 물리적 도착이나 인계 완료를 인정하지 않는다. Repeat 복귀도 진행 중인
단계가 끝났는지와 실제 RUN·캐리어·지지대 피드백을 함께 확인한다. STOP은 실행을 취소하고
이미 수집한 결과와 캐리어 완료 여부는 유지한다. 미완료 캐리어와 핸들러 소재는 정리한 뒤
새 START에서 확인한다. 정상 인계 대기 중인 공급 PCB와 단방향 NG 이송은 기존 예외를 유지한다.
볼트·검사의 실행 포인트는 새 START에서 처음부터 선택한다. 그립이나 인계가 불명확하면
현재 피드백과 필요한 소유권을 확인하며, 확인할 수 없는 상태를 완료로 처리하지 않는다.

## 파일과 실행 순서

- 기본 클래스 파일: 생성자·의존성·피드백·작업/인계 정보, 자동 실행·단계 선택,
  모션·I/O·인터록과 검사 촬영·조명·영상 처리를 한곳에 둔다.
- `.Repeat.cs`: 검사·메인/NG 컨베이어의 반복 완료 대기·복귀 진입점만 별도로 둔다.
  공급·장착·볼트의 Repeat 단계는 기본 파일의 공통 실행 루프와 switch에서 처리한다.

일반 동작을 `.Automatic.cs`, `.Motion.cs`, `.Transfer.cs`, `.Vision.cs` 등으로 다시 나누지 않는다.
Repeat에서도 사용하는 모션·인계·출력 동작은 기본 파일을 함께 사용한다.
파일 길이만 줄이기 위한 partial 분리나 별도 실행 루프를 추가하지 않는다.

실행 루프에서 다음 단계를 선택하고, 동작과 대기를 명시적으로 실행한다.
메인/NG 컨베이어와 PCB 공급은 별도 `ExecuteStepAsync`로 전달하지 않고
`RunAsync` 안의 `switch`에서 직접 처리한다.

```csharp
try
{
    BeginRun();
    while (!cancellationToken.IsCancellationRequested)
    {
        var step = GetNextStep(/* 현재 작업·모드·피드백 */);
        EnterStep(step);
        switch (step)
        {
            // 동작 단계: 장치 명령과 완료 확인을 순서대로 await
            default:
                await WaitForChangeAsync(cancellationToken);
                break;
        }
    }
}
finally
{
    // 해당 장치의 출력 정지·구독 해제
    EndRun(cancellationToken);
}
```

`GetNextStep`은 단계 선택이며 장치 명령이나 단계 확정을 하지 않는다.
`EnterStep`으로 실행 단계를 확정한 뒤 `switch`와 명시적인 `await`로 동작한다.
외부 조건이 필요하면 해당 분기에서 `WaitForChangeAsync`로 기다린다. 동작 도중 필요한
인계·장치 완료 대기는 그 동작 안에 유지한다. 동작을 끝내기 전에 다음 단계를 실행하지 않는다.
장착·볼트·검사는 현재 별도 `ExecuteStepAsync`를 사용하며, 반환값 `false`이면 실행 루프에서 기다린다.

단계 선택과 실행 함수는 유닛 내부에서만 사용하고, 외부에서는 `RunAsync`와 명시적인
수동 동작을 호출한다. 회귀 테스트는 내부 함수에 접근해 단계별로 검증한다.
레시피는 각 스테이션이 주입받은 `RecipeManager.Current`에서 읽는다.
설비 컨트롤러가 레시피 일부를 꺼내 실행 인자로 전달하지 않는다.

볼트·검사는 준비 단계에서 이번 Run의 대상 목록과 결과 소유 작업을 잡는다. 실행 호출 한 번에
포인트 하나를 처리한 뒤 루프로 돌아와 다음 단계를 선택한다. 검사는 PCB 1의 Data Matrix·볼트를
모두 처리한 다음 PCB 2로 진행한다. 티칭 미완료 대기도 같은 단계 선택 경로를 사용한다.
대상 목록은 완료/STOP 때 버린다. 장착·체결·검사는 작업 중 캐리어 재실이나 지지 상태가
바뀌면 오류로 정지한다. 피드백이 돌아와도 작업 순번을 초기화하거나 자동 재시도하지 않는다.
`ActiveBolt`·`ActivePcb`는 이 목록에서 선택된 대상만 읽는다. 조회 중 센서를 읽거나
다음 단계를 선택하지 않으며, 대상 목록이 없으면 null이다.
장착의 `ActivePcb`도 실행 단계에서 선택한 PCB만 표시한다. 내부 `TargetHeatSink`는 다음
대상을 선택하는 데 사용하고 화면에 바인딩하지 않는다. 결과 기록 후 헤드가 상승하는 동안은
현재 PCB 표시를 유지하며, STOP 때 실행 대상과 Repeat 반환 정보를 지운다.
검사 지지대 준비 역시 `RunAsync`에서 직접 움직이지 않고 선택된 단계에서 실행한다.

공급·장착 Repeat의 역인계도 일반 운전과 같은 단계 선택과 실행 switch에서 처리한다.
별도의 Repeat 실행 루프나 중복 State는 없다. 공급 준비 → 반환 PCB 제시 → 그립 확인 → 해제·이탈
→ 공급 복귀 → 정방향 재인계 순서이며, 상대 유닛 대기는 루프에 반환한다.
장착의 Repeat 작업 정보에는 결과 소유 Job과 대상 HeatSink만 보관한다.
이 정보는 진행 중인 왕복에만 사용하며 STOP 후 이어서 실행하지 않는다.
새 START는 공급 PCB 1과 장착의 첫 대상부터 시작한다. 일반 운전에서 공급이 PCB를 잡고
정상 인계 위치에서 기다리는 경우만 인계를 이어가며, 이후 픽업 순서는 PCB 1부터 시작한다.
Disabled는 화면·대기 표시로만 사용하며 미완료 인계 단계를 덮어쓰지 않는다.
출력 정지·이벤트 구독 해제 등은 각 장치 경계의 `finally`에서 처리하고,
출력 정리가 끝난 뒤 `EndRun`에서 실행 단계 표시를 정리한다. 자기 피드백 변화는 `NotifyChanged`에서
실행 중인 대기만 깨운다. SMEMA는 반입·배출 순서 안에서 처리하며,
별도 갱신 루프나 유닛 전역의 입구 통과 기록은 두지 않는다.

`GetNextStep` / `GetNextTransferStep`은 다음 동작 선택이다. 진행 중 동작을 설명할 때는
`Step`을 사용한다. 모든 유닛에서 실행 중인 동작·대기만 뜻하며, 종료 시 null로 지운다.
화면도 이 값을 사용하고 다음 동작을 현재 단계처럼 표시하지 않는다.
공급·장착만 미완료 인계를 위해 형식이 있는 `Phase`를 보관한다. `Disabled`는 이 기록을
덮어쓰지 않는다. `Phase`는 소프트웨어 이력이며 인계 위치·그립 등 실제 피드백을 대신하지 않는다.
단계 기록·실행 표시·알림은 각 유닛의 `EnterStep` 한곳에서 변경한다.
볼트·검사·컨베이어는 `BeginRun()`으로 시작하여 이전 실행 단계를 이어가지 않는다.
공급·장착은 상대 유닛의 인계 대기를 깨우기 위해 단계 변경을 `Changed`에도 전달한다.
`Changed` 이벤트와 `NotifyChanged`는 `IBTM.Device.AutoUnit`에서 공통으로 제공한다.
각 생성자는 감시할 I/O 목록을 부모에 전달하고, 멤버 초기화 후 `ObserveIo`로 구독한다.
부모는 해당 신호만 걸러 `OnInputChanged`의 개별 처리를 먼저 실행한 뒤 변경을 알린다.
상대의 변화로 자기 대기만 깨울 때는
`WakeRun`을 사용한다. 특히 검사↔NG 컨베이어 사이에서 이를 다시 `Changed`로 전달하면
알림이 순환하므로, 상태 알림과 대기 해제를 구분한다.
`Handoff`와 다음 단계 조회는 기록을 변경하지 않는다. 인계 완료 위치의 무효화는
모션 상태 변경 이벤트와 실행 루프에서 처리하며, 인계 판단은 현재 위치와 그립을 다시 확인한다.

장착의 `PreparingPlacement`는 상승·Y 이탈부터 공급의 인계 종료 확인까지 한 동작으로 처리한다.
이탈 완료 위치를 알린 뒤 같은 동작 안에서 공급의 확인을 기다리고, 이후 장착 또는 캐리어 대기로
진행한다. 확인 전에 다음 이동을 시작하면 Clear 피드백이 사라지므로 이 대기는 유지하되,
이를 위한 별도 `WaitingForSupplyClear` 단계와 외부 루프의 재선택은 두지 않는다.

단계 전환은 기본 파일과 `.Repeat.cs`의 명시적인 시퀀스에서 수행한다.
`PrepareHandoffAsync` / `PrepareReceiptAsync`는 이동 후 인계 준비를 확정하는 시퀀스 진입점이다.
티칭의 `MoveToTeachingPositionAsync`와 개별 축 이동은 시퀀스 단계를 변경하지 않는다.

공통 기반인 `AutoUnit`에는 실행 수명·변경 대기·단계 통지만 둔다. 장치 호출, 분기,
인계 판단은 각 스테이션에 명시한다. 피더처럼 감지와 보충만 하는 유닛에 별도의
단계나 범용 실행기를 추가하지 않는다. 결과 저장은 기존 저장 관리 객체가 담당한다.

## 관련 화면과 설비 초기화

- `TeachingViewModel.cs`: 화면 수명·유닛 선택, 포인트 편집·저장, 모션 명령, Live·Grab·조명.
- `OperationViewModel.cs`, `SettingsViewModel.cs`: 해당 화면의 표시·명령·설정 처리.
- `MachineController.cs`: 시작 초기화, 자동/수동 동작, Home·Stop·Reset과 안전 인터록.
- `MachineController.Repeat.cs`: 설비 Repeat 왕복 순서.

명령이라는 이유만으로 별도 `.Commands.cs`에 모으지 않는다. 명령 선언·실행·허용 조건은
해당 클래스에서 함께 찾을 수 있게 하고, 생성자의 초기화 순서는 유지한다.
MVVM·XAML 생성 코드에 필요한 `partial` 선언은 유지한다.

## 캐리어 작업과 장치 책임

메인 컨베이어는 한 번에 한 이송을 끝까지 수행한 뒤 다음 동작을 선택한다.
S1이 비어 있고 다른 이송이 선택되지 않았으면 반입 흐름에서 플레이트 DOWN·스토퍼 UP을
준비하고 READY를 켠다. 입구 감지 또는 전단 AVAILABLE을 기다리는 동안에는 다른 이송에
순서를 넘길 수 있다. 반입이 시작되면 S1 도착(Heat Sink 2) → 밀착 시간 → 벨트 정지 →
착좌 완료 → READY OFF까지 한 스텝에서 처리한다. 입구의 짧은 감지는 해당 반입 호출 안에서만 보관한다.
S3의 완료·NG 분기·갠트리 간섭 조건이 배출을 허용하면 AVAILABLE을 켠다.
배출 인계 중에는 S3 센서 이탈만으로 종료하지 않고 후단 READY OFF를 기다린다.
벨트는 OFF 감지 시각부터 설정된 추가 시간만큼 더 돌린다. 다른 이송 중에는 새 반입을
허용하지 않는다. STOP·수동 벨트 종료·역송 종료의 출력 OFF는 정지 경계에서 수행한다.

PCB 공급의 Front1은 두 슬롯 픽업 완료를 READY OFF로 알리므로 메인 컨베이어와 다르다.
STOP 시 전단 AVAILABLE이 남아 있으면 READY를 유지하고, 피드백 불명은 완료로 처리하지 않는다.
출력 소유권은 다음과 같다. 수동 명령도 해당 유닛의 실제 인터록을 거친다.

| 유닛 | 담당 출력 |
| --- | --- |
| PCB 공급 / 장착 | 각자 그리퍼·고정·회전·승강, 공급의 Front1 |
| 볼트 스테이션 | 헤드·진공·이스케이프·슈팅 |
| 볼트 피더 | 보충 RUN과 미감지 감시 |
| 검사 / NG Transfer | 픽업 승강·그리퍼, S3 착좌 인계 |
| NG 컨베이어 | 셔틀·벨트·스토퍼·배출/완료 버튼 램프 |

별도 `StationWork` 계층은 두지 않는다. `ConveyorStation.cs`가 기존 S1/S2/S3
지지대 객체에 Job 식별, 결과, 완료 여부와 결과 인계를 보관한다. 센서 변화는 Job을 지우거나
완료를 해제하지 않는다. START 확인에서 미완료 캐리어가 남아 있으면 차단하고, 빈 스테이션만
승인된 START에서 정리한다. 완료 캐리어는 완료 상태를 유지해 다음 스테이션으로 이송한다.
자동 이송은 빈 목적지를 준비할 때 Job을 새로 만들며, 이전 Job의 결과 쓰기와 완료 요청은 거부한다.
이송 결과 인계는 출발 Job과 도착 시 확인한 Job을 함께 넘긴다. 목적지 Job 확인과 결과 교체는
같은 잠금 안에서 수행하여 교체된 캐리어에 이전 결과를 덮어쓰지 않는다.

Enabled와 공정 준비 조건은 `PcbPlacer`, `BoltFasteningStation`, `InspectionStation`이 판단한다.
검사 요청·착좌 요청·NG 인계 소유권·공유 축 및 픽업 인터록은 `InspectionStation`에 있다.
메인 컨베이어는 S1/S2의 `ConveyorStation`과 `InspectionStation`을 직접 참조한다.
UI와 결과 저장도 각 스테이션의 `Station`을 사용하며 별도의 Work DI 등록이나 표시용 복사본은 없다.
티칭 화면의 I/O 목록은 하드웨어 설정과 공유 `IoSignals`로 구성한다.
목록을 만들기 위해 스테이션을 생성하거나, 지지대 객체에 화면 구성 함수를 두지 않는다.

`MotionStatus`는 모니터가 수집한 화면용 피드백과 변경 알림을 보관한다.
시퀀스의 위치·정지·그립 위치 유지 판단은 `MotionServiceBase`에 실제 모션 장치를 넘겨 현재
피드백으로 확인한다. `MotionStatus`에 `live` 인자로 표시값과 장치 조회를 전환하는 경로는 두지 않는다.
화면에서 피드백을 읽을 수 없으면 null/Unavailable을 유지한다.

검사 스테이션 생성 시 NG 컨베이어에 인계 피드백을 한 번 연결한다. 피드백이 연결되지 않은
상태는 픽업 간섭 해제로 판단하지 않는다. 검사 변경은 NG 실행 대기만 깨워서 양쪽 Changed 알림이 순환하지 않게 한다.
NG Repeat 완료 대기는 검사 인계 변경도 직접 구독한다. 센서와 실행 단계가 그대로여도
명시적인 해제로 미완료 인계가 끝나면 대기를 다시 판단한다.
Inspection을 꺼도 미완료 인계와 픽업 상승 조건은 유지한다. Enabled는 공정 실행 선택이며,
컨베이어 반입·배출·역송의 물리적 간섭 해제를 대신하지 않는다.
메인 컨베이어만 켠 Repeat는 S3 지지대가 이미 준비된 경우 역송할 수 있다. S3로 새로 이송한 뒤
백업 상승이 필요하면 꺼진 검사 축을 임의로 이동하지 않고 준비를 기다린다.
