# Station 3 및 메인·NG 컨베이어 실장비 검증 계획

검토일: 2026-09-06. 현재 소스 기준의 검증 계획이며, 실장비 시험 완료 기록은 아니다.
이 문서를 작성하면서 실제 보드·모션·공압을 구동하거나 현장 설정을 변경하지 않았다.

## 1. 확정된 입고 범위

- Station 3 검사부: 검사 카메라와 공용 X/Y 갠트리. Z축 없음.
- NG Transfer: 위 검사 X/Y를 함께 사용하는 캐리어 픽업.
- NG Shuttle: 캐리어를 아래 NG 컨베이어로 내리는 유닛.
- 메인 컨베이어 및 Station 1·2·3의 스토퍼·백업 플레이트·감지 센서.
- NG 컨베이어: 셔틀이 내려오는 3번 위치와 적재 위치 1·2.
- PCB Supply·Placement·볼트 체결 작업은 이번 자동 검증에서 제외한다.

공정 유닛을 끄는 것과 컨베이어의 해당 정차 위치를 제거하는 것은 다르다.
Station 1·2 공정 OFF여도 메인 컨베이어는 그 위치에서 캐리어를 받고, 안착시키고, 다음 위치로 보낸다.

최종 통합 검증에서 켤 설정은 아래 5개다. 실행 루프는 **4개**다.

| 설정 | 값 | 실행 책임 |
| --- | --- | --- |
| `MainConveyor` | ON | 메인 이송, 각 위치 스토퍼·플레이트, 전후단 SMEMA |
| `Inspection` | ON | Station 3 볼트 유무 검사 |
| `NgCarrierTransfer` | ON | 검사와 같은 `InspectionStation` 루프에서 NG 캐리어 이송 |
| `NgShuttle` | ON | NG 컨베이어로 하강·복귀 |
| `NgConveyor` | ON | 3 → 1/2 이동, 적재 및 작업자 배출 |
| `PcbSupply`, `PcbPlacement`, `BoltFastening`, 두 `BoltFeeder` | OFF | 이번 자동운전 제외 |

`UnitSettings` 변경은 저장 후 프로그램 재시작해야 적용된다.

## 2. 반영한 소프트웨어 조건과 설치 전제

### A. 검사 XY의 이동·홈 조건

`InspectionGantry`에서 NG 픽업 상승 DI를 확인한 뒤 XY 이동을 허용한다.
자동 검사·NG 이송뿐 아니라 Jog, Move To, 캐리어 스캔, 학습 포인트 촬영에도 같은 조건을 적용한다.
XY 이동 중 상승 피드백을 잃으면 알람과 공통 Stop으로 중지한다.

Home은 전체·검사 축 개별 명령 모두 다음 순서다.

1. NG 픽업의 캐리어 감지 ON이면 Home을 허용하지 않는다. 작업자가 캐리어를 안전하게 내려놓고 해제한 뒤 시작한다.
2. 캐리어 미감지 확인 → 빈 그리퍼 Open 피드백 확인 → 픽업 Up 피드백 확인 → XY Home.
3. 준비 중 Stop·취소·피드백 타임아웃이면 XY Home으로 넘어가지 않는다. 홈 중 캐리어가 감지돼도 정지한다.

Home 명령으로 감지 중인 캐리어를 자동으로 떨어뜨리지 않는다.
이 소프트웨어 조건과 별도로, 빈 픽업을 현재 XY에서 올릴 때의 실제 기구 여유를 현장에서 확인한다.

근거: `InspectionGantry`, `MachineController.HomeAsync`,
`ManualHardwareViewModel`, `StationTeachingViewModel.Motion/Camera`.

### B. 비활성 작업은 컨베이어 실행과 무관하게 통과 가능

각 `StationWork`가 활성 설정을 받아, 비활성 공정은 별도의 완료 명령 없이 통과 가능하게 판단한다.
MainConveyor가 비활성 공정의 완료 상태를 대신 기록하던 코드는 제거했다.
`Inspection=OFF`, `NgCarrierTransfer=ON`, `MainConveyor=OFF`에서도 부팅 시 이미 들어온 DI로 판단한다.
실제 캐리어 존재·스토퍼·픽업·셔틀 조건은 그대로 DI에서 확인한다.

근거: `StationWork.Completed`, `InspectionStation.CarrierReadyForNg`.

### C. 유닛 OFF는 IO 카드 미설치를 허용하는 설정이 아니다

Physical 제어는 AlphaMotion과 AJIN 초기화, 전체 `.mot` 로드, 전체 논리 DI/DO 맵 조회를 수행한다.
비활성 유닛의 축 설정 항목을 삭제하거나, 미설치 보드까지 자동으로 제외된다고 가정하지 않는다.
실제 설치 보드와 전체 매핑이 맞지 않으면 먼저 이 단계에서 막힌다.

또한 프로그램 초기화는 읽기 전용이 아니다. 활성 축에 Servo ON을 명령하고,
컨베이어·피더·슈팅·공급 SMEMA 등 정지 출력을 내린다.
Home/Start를 누르지 않았다는 것만으로 출력이 전혀 없다고 판단하면 안 된다.

근거: `PhysicalIoService.Initialize/CheckReady`, `AjinController.Initialize`,
`AjinMotionService.Initialize`, `MachineController.CheckHardwareAsync/StopRunOutputs`.

### D. 티칭값은 해당 설정 파일에 저장

NG 픽업·셔틀 배치 Teach는 `NgCarrierTransferSettings`를 저장한다.
스캔 양 끝은 `InspectionGantrySettings`, 기준핀은 `CarrierReferenceSettings`에 저장한다.
저장 대상 선택은 `StationTeachingPoints.SaveAsync` 한 곳에서 관리한다.
현장에서는 Teach 후 재시작해 실제 티칭값이 유지되는지도 확인한다.

## 3. 입고 전 준비할 것

- 실제 설치 IO 보드·모듈 목록, 최종 배선표, AJIN `.mot`, 보드·카메라 드라이버.
- 실행 파일과 같은 배포 폴더의 `Settings`, 실제 티칭 레시피, 검사 모델.
- 전후단 설비 또는 전장 담당자가 승인한 SMEMA 시험 장치. 후단에는 실제 수취 공간이 있어야 한다.
- 검증용 캐리어, 히트싱크 한쪽/양쪽 구성, 체결 완료품, 알려진 볼트 누락품.
- 기구·전장 담당자와 각 동작의 허용 영역, 초기 공압 상태, 안전한 시운전 속도 확인.

Virtual 개발 설정과 임의 좌표를 실장비 설정으로 복사하지 않는다.
`Virtual` 빌드는 장치 드라이버를 Virtual로 강제하므로 현장 제어용으로 쓰지 않는다.
현장용 일반 빌드에서 `Control=Physical`을 확인하고, 실제 영상 검증 단계에서는 카메라와 검사 알고리즘도 확인한다.
볼트 체결은 OFF이며 ADC 통신은 이번 검사·이송 검증의 선행 조건이 아니다.

현재 두 컨베이어 제어는 축 펄스 명령이 아니라 `Run / Reverse / NormalSpeed` DO다.
현물 드라이버가 이 신호를 어떻게 사용하는지, 실제 속도·정지 거리는 별도로 확인해야 한다.
UI 모션 속도나 타임아웃 값을 바꿔 컨베이어 정지 거리가 해결된다고 가정하지 않는다.

배선·수동 투입·걸림 제거는 현장 에너지 격리 절차로 진행한다. 프로그램 Stop은 전기·공압 격리를 대신하지 않는다.
안전장치 기능 시험은 전장 담당자의 승인된 절차로 시행하고, 인터록을 끄거나 DI를 우회하지 않는다.
이는 일반적인 안전 작업 원칙이며 이 설비의 안전 적합성 인증을 의미하지 않는다.
참고: [HSE 안전한 정비와 에너지 격리](https://www.hse.gov.uk/work-equipment-machinery/maintenance.htm).

## 4. 검증 순서와 통과 기준

한 단계가 통과한 후 다음 단계의 자동 유닛을 켠다. 처음부터 전체 Auto로 확인하지 않는다.

### 1단계 — 입력과 안전 회로

자동 유닛은 모두 OFF로 시작하되, 위 초기화 출력의 영향을 전장 담당자와 확인한 뒤 프로그램을 실행한다.
실제 센서·접점 하나를 변화시켰을 때 DI 창과 운용 화면에서 같은 의미로 나타나는지 대조한다.
IO 번호는 Settings의 매핑과 최종 배선표에서 확인한다. 이번 검토에서는 엑셀·실배선을 재대조하지 않았다.

| 구역 | 확인할 입력 |
| --- | --- |
| 공통 | E-stop 2개, 도어 6개, Auto/Manual, Reset, 서보 메인 접촉기, 저압 |
| 메인 | 전단 Available, 후단 Ready, 입구·출구 센서, 세 위치 캐리어·스토퍼 상하·플레이트 상하 |
| Station 3 | 히트싱크 1·2 감지 |
| NG Transfer | 픽업 상하, 그리퍼 열림/닫힘, 캐리어 감지 |
| NG Shuttle | 상하, 캐리어 감지 |
| NG 컨베이어 | 1·2·3 감지, 스토퍼 상하, 배출 요청·완료 버튼 |

현재 소프트웨어는 E-stop Pressed·Door Open·Air Pressure Low의 ON을 이상으로, Servo Main Contactor On의 ON을 정상으로 해석한다.
실배선 극성과 맞는지 확인해야 한다.

통과 기준: 다른 유닛의 DI가 대신 켜지지 않고, 신호 의미·정상 극성이 일치한다.
도어/비상정지 해제만으로 자동운전이 재개되지 않아야 한다.
사용자가 설명한 Auto 도어 개방 → RTEX 알람·서보 탈락, Manual 전환 또는 도어 닫힘 후 Reset 복구도 확인한다.
프로그램 Reset만으로 하드웨어 접촉기가 복구된다고 가정하지 않는다.

### 2단계 — 공압과 컨베이어 단동

무부하·허용된 공간에서 대상 하나씩 확인한다. DO 창은 저수준 정비 접근이며 자동 시퀀스의 간섭 확인을 대신하지 않는다.

- 각 스토퍼·플레이트, NG 픽업·그리퍼, 셔틀을 실제 동작과 DI로 대조한다.
- 지정 끝단 DI뿐 아니라 반대쪽 DI 해제도 확인한다. 두 DI가 모두 ON이거나 모두 OFF인 상태를 정상 끝단으로 취급하지 않는다.
- DO ON만 보고 완료로 판정하지 않는다. 기존 `TimeoutMilliseconds`와 현장 응답 시간을 대조한다.
- 메인/NG 모터 방향과 Stop 시 실제 정지, 이동 중 센서 체류 시간을 확인한다.

통과 기준: 실제 동작·끝단 피드백이 일치하고, 끼임·간섭·예상치 못한 다른 출력이 없다.
응답이 없으면 원인을 먼저 찾는다. 타임아웃만 무작정 늘리지 않는다.

### 3단계 — 검사 XY, 티칭, 카메라

검사 XY와 NG Transfer는 공용 축이며 Station 3 Z축은 없다. 2-A의 이동·홈 조건을 현장에서 대조한다.
`Inspection`·`NgCarrierTransfer`만 ON으로 저장·재시작하고 Auto Start는 하지 않는다.
모두 OFF인 상태를 유지하면 검사 축이 초기화되지 않으며, NG Transfer OFF이면 NG 티칭 항목도 표시되지 않는다.

- 최초에는 캐리어 없는 상태에서 NG 픽업 상승 및 기구 여유를 확인한다.
- 실제 축 번호, 펄스당 길이, 이동 범위, `.mot` 홈 방식·방향, 프로그램 홈 속도를 확인한다.
- 승인된 시운전 조건으로 Home 후 좌표 단위와 이동 방향, 정지·인포지션을 확인한다.
- NG 캐리어 픽업 XY, 셔틀 배치 XY는 현장에서 각각 티칭한다. 기본 `(0,0)`은 검증된 위치가 아니다.
- NG 티칭 후 재시작해 두 좌표가 그대로 복원되는지도 확인한다.
- 카메라 영상의 초점·노출·조명 채널과 mm/pixel을 확인한다.
- 스캔 양 끝 XY 티칭 → 캐리어 타일 촬영 → 이미지 배치/스케일 확인 → 이미지에서 좌상단·우하단 기준핀과 볼트 클릭 티칭 순서다.
- 현재 기준핀·볼트는 이미지 티칭 항목이므로 현재 위치 Teach와 Move To 버튼은 사용하지 못한다.
- 티칭 좌표와 실제 영상의 일치는 학습 화면의 티칭 포인트 촬영이나 4단계 검사 촬영으로 재확인한다.

통과 기준: 화면상 위치뿐 아니라 실제 카메라 중심과 티칭 위치가 일치한다.
검사만 켜면 체결용 Z·헤드 기준점은 필요 없지만, 검사 볼트 XY·두 기준핀은 필요하다.
모델은 최초 판정 때 로드될 수 있으므로 Start 가능 여부만으로 모델 준비를 판정하지 않는다.

### 4단계 — Station 3에 직접 안착시켜 검사

`Inspection=ON`, 메인·NG 자동 이송은 OFF로 시험한다.
직접 투입·안착은 안전하게 정지·격리한 상태와 승인된 작업 절차에서 수행한다.
검사 시작 조건은 캐리어 감지 + 플레이트 Up + 스토퍼 Down이다.
NG Transfer 자동을 꺼도 픽업 Up + NG 캐리어 미감지는 검사 진입에 필요하다.

- 히트싱크 1만 있음 / 2만 있음 / 둘 다 있음: 검사 시작 시 감지된 쪽의 볼트만 검사한다.
- 둘 다 없음: 촬영할 제품이 없으며 완료 후 NG로 분류한다.
- 모든 볼트 있음 / 알려진 한 볼트 누락: 실제 원본·마스크·판정을 대조한다.
- 검사 도중 Stop 후 Start: 현재 DI로 대상을 다시 정하고 미완료 검사를 처음부터 수행한다.

검사 도중 히트싱크 DI 변화만으로 작업을 취소하거나 완료·판정을 뒤집지 않는다.
캐리어 안착, NG 픽업 간섭 및 설비 안전 조건은 계속 적용한다.

통과 기준: 없는 쪽을 검사하지 않으며, 알려진 누락품을 OK로 통과시키지 않는다.
`Simulated` 결과는 이송 연동 확인에만 사용할 수 있고 실제 검사 품질 통과로 기록하지 않는다.
일부 샘플 통과와 생산 품질 승인도 구분한다.

### 5단계 — NG 배출 연동

검사와 NG Transfer·Shuttle·Conveyor를 켜고 메인은 OFF로 둔다.
4단계에서 판정한 NG 캐리어로 시작한다. 검사를 끈 NG 단독 시험도 2-B 조건으로 별도 확인한다.

1. Station 3 → NG Transfer 픽업 → 픽업 상승 → 셔틀 위 이동.
2. 상승해 있고 비어 있는 셔틀에 내려놓기 → 셔틀 캐리어 감지 → 픽업 상승.
3. 셔틀 하강 → NG 3번 감지 → 비어 있는 1번까지 이송 → 셔틀 복귀.
4. 1번 점유 시 다음 캐리어는 2번까지, 1·2번 점유 시 다음 캐리어는 3번에 적재.
5. 만재 시 추가 캐리어를 내려놓거나 밀어 넣지 않는다. Station 3의 NG는 기다린다.
6. 실제 배출 요청·완료 버튼으로 배출하고 남은 캐리어 정렬과 다음 수취를 확인한다.

통과 기준: 픽업이 내려와 있는 동안 셔틀이 하강하지 않고, 다음 수취 공간이 없으면 이송하지 않는다.
`AlarmCarrierCount`는 현재 램프·부저 기준이다. 설정 개수 도달 자체가 전체 자동 정지는 아니다.
적재 개수 표시와 3개 센서를 대조하고, 실제 만재에 따른 수취 차단은 별도로 확인한다.

### 6단계 — 메인 컨베이어

먼저 MainConveyor만 켜서 기계 이송을 확인하고, 이어 검사·NG 계통을 함께 켠다.
다른 공정 OFF는 해당 작업을 완료 처리하는 뜻이지 제품 품질을 보증하는 뜻은 아니다.
검사·NG가 모두 OFF인 단독 시험에서도 빈 캐리어는 Station 3에서 NG로 대기할 수 있다.
후단 배출 단독 시험에는 실제 히트싱크가 감지되는 검증용 캐리어를 사용한다.

- 전단 Available 및 수취 조건 확인 → Station 1 스토퍼 Up/플레이트 Down → Run.
- 입구 감지 후 전단 Ready 해제 → Station 1 캐리어 감지 시 정지 → 안착.
- Station 2가 비어 있을 때 1 → 2, Station 3가 비어 있고 수취 가능할 때 2 → 3.
- 이동 전에 도착 위치 스토퍼가 올라와 있어야 한다. 도착 감지 후 모터 정지 → 플레이트 Up → 스토퍼 Down.
- 보내고 받는 위치만 이송을 위해 플레이트를 내린다. 작업 중인 다른 캐리어는 플레이트 위에 남는다.
- 정상품은 후단 Ready OFF에서 대기하고, Ready ON 후 출구 센서 ON → OFF까지 확인하여 배출을 끝낸다.

통과 기준: 벨트에 내려와 움직이는 캐리어는 하나이고, 각 위치의 실제 도착 신호로 정지한다.
센서가 ON이어도 관성으로 밀리지 않는지는 실장비에서 확인한다. 소프트웨어 테스트로 정지 거리를 보증할 수 없다.
후단 수취 설비가 없으면 출구 밖 배출 시험은 보류한다.

### 7단계 — 대기, Stop, 재시작

- Station 3 검사 중 Station 1 → 2 이동 가능. Station 3 점유 중 2 → 3 진입 금지.
- 진행 중인 이송이 없고 다음 이송을 선택할 때, 뒤쪽 이송과 앞쪽 수취가 동시에 가능하면 뒤쪽 우선. 이미 시작한 수취를 중단하고 바꾸는 의미는 아니다.
- 후단 Ready 대기 중 정상품 유지, NG 적재 공간 대기 중 NG 캐리어 유지.
- 검사 이동 / 캐리어 이송 / NG 픽업·놓기 / 셔틀 하강 / NG 적재 각각에서 Stop.
- Stop 시 각 축과 Run 출력이 멈추고 공압 출력은 유지되는지 확인한다.
- 안전 조건 복구 후 명시적으로 Start했을 때 현재 DI·축 위치로 올바른 상태를 선택하는지 확인한다.
- 프로그램 종료·재시작은 Stop/Start와 별개로 확인한다. 재시작이 공정 결과를 복원한다는 가정은 하지 않는다.
- 캐리어가 이미 각 센서에 있는 상태로 부팅한 경우와 부팅 후 도착한 경우를 비교한다.
- 센서 사이에 멈춰 존재를 직접 알 수 없는 구간은 별도 기록한다. 감지되지 않은 위치를 기억한다고 가정하지 않는다.

안전장치·통신 이상은 우선 Virtual에서 검증하고, 현장에서는 승인된 무부하 시험 절차로만 재현한다.
가동 중 커넥터를 임의로 뽑거나 캐리어를 손으로 막아 고장을 만들지 않는다.

## 5. 기록과 다음 작업

각 시험은 `초기 DI/좌표 → 누른 명령 → 실제 동작/도착 DI → 판정`으로 기록한다.
실행 버전, 활성 유닛, Settings/레시피 버전과 변경한 매핑·티칭값을 함께 남긴다.
속도·홈 방향·타임아웃의 현장 숫자는 기구·전장 확인 없이 이 문서에서 확정하지 않는다.

다음 단계는 실제 설치 보드·배선·`.mot`·공압 상태 확인 후 위 1단계부터 현장 검증하는 것이다.
Virtual 회귀 시험에는 캐리어 감지 중 Home 차단, 준비 도중 Stop, 상승 후 XY Home,
XY 이동 중 픽업 상승 피드백 상실, 비활성 검사 작업의 초기 DI 판단을 포함한다.
WPF 검증에서는 NG 티칭 저장·재로드와 이동 버튼 조건을 확인한다.
소프트웨어 시험은 실제 모션 정지 거리·전기 안전·기구 간섭·검사 품질 검증을 대신하지 않는다.

2026-09-06 수정 후 확인 결과:

- Release·Virtual 전체 빌드: 경고 0, 오류 0.
- Virtual 회귀 테스트: 81개 통과. 컨베이어 Run 준비 중 취소, 실린더 양쪽 DI 모순,
  Station 2 복구 시 기존 실측 NG·토크 보존, Stop/동작 종료 경합을 포함한다.
  Station 1~3 작업 중 히트싱크 DI 변경, Stop 후 대상 재선정,
  완료·NG 결과 보존과 검사 비활성 시 기존 배출 조건도 확인했다.
  복구 창에서 생략된 항목은 보존하고 명시적으로 체크 해제한 항목만 재작업 처리한다.
- 입고 구성의 부분 운전: Supply·Placement·체결·두 피더 OFF, 메인·검사·NG 계통 ON.
  검사 XY만 Home, 나머지 축 Servo OFF·미원점 상태에서 Start 가능하며,
  Station 1·2 경유 후 정상 후단 배출 및 볼트 누락 영상의 NG 적재를 확인했다.
  비활성 유닛의 ON 출력·ADC 프레임은 없고, 공통 정지용 OFF 출력은 유지한다.
- ADC 진단 창: 49개 확인 통과. 실제 ADC가 아닌 Virtual/시험 대역 사용.
- 전체 WPF 가상 운전: 정상 배출, 체결 NG 적재, 후단 대기, Stop/재시작, 남은 캐리어 순서 배출 통과.
- 티칭·학습: NG 설정 저장/재로드, Home 준비 타임아웃/Servo Off, Live 오류 후 재시작,
  수동 IO 대기·연속 축 이동·촬영 중 Stop, 저장 전 Supply Buffer Z 이동 및 CPU 학습 실행 확인.
- 전체 WPF 예상치 못한 예외 로그와 전체 WPF·ADC 바인딩 오류 로그: 비어 있음.
- 창 종료 6개 상황(Home, Supply 이동, 체결, 검사 이동, 촬영, 수동 Jog):
  동작 정리·ADC Stop 완료 후 DI 해제 확인.

CPU 학습 실행 확인은 모델 정확도나 실제 볼트 누락 검출 성능 검증이 아니다.
Physical IO 재연결은 이전 감시 종료 후 재초기화하도록 수정했다.
Virtual에서 Reset DI 복구 경로를 확인했으며, 실제 보드 통신 장애·재연결은 현장에서 별도 검증한다.
