# 데이터 매트릭스 판독과 사진 촬영

`InspectionStation`이 자동 검사 순서와 이동·촬영·판정을 함께 담당한다.
촬영·조명·Live View 코드도 기본 파일 `InspectionStation.cs`에 둔다.
`InspectionStation.Station`의 Job이 캐리어별 결과와 완료 소유권을 보관한다. 검사 요청·착좌 요청과 NG 인터록 상태는 기본 파일 `InspectionStation.cs`에서 관리한다.
검사와 NG 이송은 하나의 `InspectionStation`이 소유한다. 자동 순서·집기·놓기·장치 동작을
기본 파일에 모은다.
자동 루프는 `NextStep`으로 다음 동작을 선택하고 `ExecuteStepAsync`로 실행한다.
실행 내부의 `EnterStep`으로 현재 단계를 알리고, 순차 동작을 끝까지 기다린다.
실행이 외부 조건 대기를 반환하면 루프에서 `WaitForChangeAsync`로 대기한다.
현재 단계가 물리적 위치나 인계 완료를 대신하지 않는다.
후단 배출은 대기 위치 이동을 마친 `Waiting` 단계에서 픽업 상승·미완료 인계 없음·축 정지를 확인한다.
대기 좌표를 다시 비교하지 않으며, 새 START에서도 복귀 이동이 끝나기 전에는 배출하지 않는다.
`NgCarrierConveyor.cs`는 셔틀·벨트 순서와 장치 동작을 처리한다.
빈 셔틀이 내려가 있으면 인계 해제와 픽업 상승·그리퍼 열림을 확인한 뒤 상승시켜 다음 캐리어를 받는다.

각 PCB의 데이터 매트릭스를 판독한 뒤 등록된 볼트의 검사 XY마다 이동해 사진을 촬영한다.
볼트 사진은 저장·표시용이며 ROI나 기준 이미지가 없어도 촬영한다. 볼트 유무 판정은 하지 않는다.
사진은 볼트 GUID, 촬영 시각과 함께 원본 PNG로 저장하고 결과 화면에서 조회한다.
사진에는 판정·ROI가 없으며 체결 결과와 회전수 판정은 그대로 유지한다.
데이터 매트릭스 미인식의 NG 반영 여부는 `ExcludeDataMatrixFromNg` 설정을 따른다.

Teaching의 Inspection Gantry는 포인트 추가·삭제, 좌표 기록, Live·Update Image + Light과 촬영 조명을 담당한다.
Live 조명값은 화면에서만 보관하며, 포인트를 선택하면 저장된 조명값을 불러온다.
Save X/Y + Image는 좌표와 기준 영상을 저장하고, Update Image + Light는 기존 포인트의 영상과 조명만 갱신한다.

별도 Inspection Teaching은 저장된 기준 영상이나 검사 결과 영상을 불러와 ROI·판독 설정을 조정한다.
카메라나 축을 제어하지 않으므로 자동 운전 중에도 사용할 수 있다. 볼트 사진은 원본을 표시한다.
Data Matrix에만 ROI 편집·이진화 미리보기·재판독을 제공하며 판독 옵션과 임계값 탐색 범위를 조정한다. Data Matrix는 처음부터 최소~최대 임계값을 지정 증가폭으로 탐색한다.
증가폭이 범위를 나누어떨어지지 않아도 최대값은 마지막에 포함하며, 처음 성공하면 탐색을 끝낸다.
각 임계값에서 일반 판독 → 실패 시 다일레이션 판독 → 실패 시 다음 임계값 순서로 진행한다.
점 확장 반경이 1 이상이면 그 임계값의 이진 영상에서 검은 점을 지정 반경만큼 한 번 확장한다
(1픽셀=3×3, 0=확장 끔, 최대 5픽셀). 어느 단계든 처음 성공하면 즉시 종료한다.
기본값은 0~255, 증가폭 5, 확장 반경 1이다. 이전 단일 BinaryThreshold 값은 사용하지 않는다.
검사 화면에는 성공한 시도(전체 실패 시 마지막 시도)의 임계값과 처리 영상을 표시한다.
같은 Threshold와 Dilated 여부를 PCB 결과 DB의 PcbImages.Metadata에 저장한다.
기존 결과처럼 해당 값이 없으면 null을 유지하며, 과거 판독 조건을 추정하지 않는다.
탐색 범위와 원본 영상은 바꾸지 않으며 탐색 도중 STOP/취소를 확인한다.
활성 레시피는 화면과 자동 검사가 같은 객체를 사용하며 편집값을 바로 읽는다.
Save는 현재 검사 설정을 DB에 보관한다. Gantry에서 기록한 좌표와 촬영 조명, 저장된 생산 결과는 덮어쓰지 않는다.

카메라·조명·검사축·Data Matrix 읽기·검사 결과와 NG 이송은 기존 Inspection
프로젝트가 담당한다. 학습·라벨링·모델 관리·자동 학습 이미지 수집 및 Torch 의존성은
제거했다. 데이터 매트릭스 판독은 실제 카메라와 가상 카메라에서 같은 경로를 사용한다.

## LVDT 높이 측정

각 PCB마다 데이터 매트릭스 판독 → 모든 볼트 사진 → 기준면 세 점 측정 → 각 볼트 측정 순서다.
사진과 측정 중 S3 백업은 하강 상태를 유지한다.
기준면은 PCB 또는 히트싱크의 같은 기준면에 세 점을 티칭한다. 일직선인 세 점으로는 평면을 만들 수 없다.
별도 재질 선택은 없으며, 선택한 기준면에 맞춰 볼트별 최소·최대 높이를 레시피에 저장한다.

- 티칭 → 검사: PCB별 기준면 1·2·3을 카메라 중심으로 XY 기록
- 검사 → 볼트 선택: 최소·최대 높이 입력 후 저장
- 설정 → 카메라 조명: 카메라 중심에서 같은 점을 LVDT로 짚기 위한 X/Y 이동량, LVDT 통신 설정
- I/O 매핑: LVDT 하강은 실린더 1의 출력 77 사용. 상승·하강 입력은 번호 미확인으로 -1 유지. 실린더 2는 사용하지 않음

측정 XY는 카메라 티칭 XY에 오프셋을 더한다. XY 도착 → LVDT 하강 확인 → START·측정값 수신 → LVDT 상승 확인 순서다.
LVDT가 올라오지 않으면 다음 XY 이동은 실행하지 않는다. 통신 실패·취소에서는 측정값을 만들거나 다음 위치로 이동하지 않는다.
다시 START하면 LVDT를 상승시키고 사진과 기준면부터 새로 측정한다.

볼트 높이는 해당 XY에서 계산한 기준면 높이를 원측정값에서 뺀 값이다. 허용 범위의 양 끝값은 포함한다.
히트싱크를 기준으로 삼으면 PCB 두께와 들뜸도 상대 높이에 포함된다.
PCB 결과에 기준면 세 측정값·XY, 볼트별 원측정값·기준 높이·허용 범위·시각을 저장한다.
결과 창의 높이 측정 탭과 CSV에서 조회하며 저장된 결과는 이후 레시피 변경으로 다시 판정하지 않는다.

## 히트싱크 피듀셜

레시피의 PCB별 피듀셜 보정을 켜면 촬영 전에 히트싱크 원형 구멍 두 곳을 찾는다.
검출은 이진화 → 외곽 윤곽 → 원형 여부·등록 크기·MatchShapes(I3) 확인 → 원 맞춤 순서다.
밝기 템플릿 매칭은 사용하지 않는다. 어두운 구멍이 기본이며 조명에 따라 밝은 마크를 선택할 수 있다.
서로 다른 두 구멍으로 XY 이동·회전만 구한다. 두 기준점의 중점을 기준으로 적용하고 배율은 변경하지 않는다.
카메라 해상도(mm/pixel)는 설정 → 카메라 조명에서 입력한다. 영상 오른쪽은 장비 X+, 아래쪽은 Y− 방향이며 X·Y에 같은 해상도를 사용한다. 두 PCB에 공통인 장비 설정으로 저장한다.

보정은 데이터 매트릭스·볼트 사진, 기준면 세 점, 볼트 높이 측정의 실행 좌표에 적용한다.
카메라→LVDT 오프셋은 장비 축 방향의 고정 이동량이므로 보정 후 더한다.
저장된 티칭 좌표와 체결 스테이션 좌표는 바꾸지 않는다. 히트싱크 위에서 PCB만 따로 움직인 양은 이 보정으로 알 수 없다.
마크 없음·복수 후보·원 맞춤 실패·두 점 위치 중복은 피듀셜 실패로 기록하고, 해당 PCB의 나머지 검사는 보정 없는 티칭 좌표로 진행한다. 이전 보정값은 재사용하지 않는다.
피듀셜 NG 제외 설정은 최종 NG 반영만 바꾼다. OFF면 실패한 PCB는 전체 검사 완료 후 NG, ON이면 다른 검사 결과로 판정한다. 실패 원인과 당시 제외 여부는 결과 화면·CSV에 남는다.
미등록·해상도 불일치와 같은 설정 오류, 모션·카메라·통신 실패 및 취소는 계속 정지 경로로 전달한다.
