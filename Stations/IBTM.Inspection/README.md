# 밝은 면적 비율 검사

`InspectionStation`이 자동 검사 순서와 이동·촬영·판정을 함께 담당한다.
촬영·조명·Live View 코드도 기본 파일 `InspectionStation.cs`에 둔다.
`InspectionStation.Station`의 Job이 캐리어별 결과와 완료 소유권을 보관한다. 검사 요청·착좌 요청과 NG 인터록 상태는 기본 파일 `InspectionStation.cs`에서 관리한다.
검사와 NG 이송은 하나의 `InspectionStation`이 소유한다. 자동 순서·집기·놓기·장치 동작을
기본 파일에 모은다.
자동 루프는 `NextStep`으로 다음 동작을 선택하고 `ExecuteStepAsync`로 실행한다.
실행 내부의 `EnterStep`으로 현재 단계를 알리고, 순차 동작을 끝까지 기다린다.
실행이 외부 조건 대기를 반환하면 루프에서 `WaitForChangeAsync`로 대기한다.
현재 단계가 물리적 위치나 인계 완료를 대신하지 않는다.
후단 배출은 대기 위치 이동을 마친 `Waiting` 단계에서 픽업 상승·미완료 인계 없음·축 정지를 확인한다.
대기 좌표를 다시 비교하지 않으며, 새 START에서도 복귀 이동이 끝나기 전에는 배출하지 않는다.
`NgCarrierConveyor.cs`는 셔틀·벨트 순서와 장치 동작을 처리한다.
빈 셔틀이 내려가 있으면 인계 해제와 픽업 상승·그리퍼 열림을 확인한 뒤 상승시켜 다음 캐리어를 받는다.

볼트 검사는 `BinaryRegionAnalyzer.Check`에서 저장된 사각형 ROI를 원본 크기로 처리한다.

1. BGR 픽셀을 밝기 `(299R + 587G + 114B + 500) / 1000`으로 변환한다.
2. 밝기가 `BrightnessThreshold` 이상이면 흰색, 미만이면 검은색으로 만든다.
3. `밝은 픽셀 수 / ROI 전체 픽셀 수`가 `MinimumBrightRatio` 이상이면 볼트 있음으로 판정한다.

밝기와 최소 비율은 볼트별 설정이다. 개별 값이 없는 기존 볼트는 종전 레시피 공통값을 사용하며,
신규 볼트는 그 기본값에서 시작한다(새 레시피 기본: 밝기 128, 최소 비율 1%). 실제 합격 기준은 촬영 영상으로
맞춰야 한다. 기준값과 같은 밝기 및 최소 비율과 같은 결과는 합격이다.

Teaching의 Inspection Gantry는 포인트 추가·삭제, 좌표 기록, Live·Update Image + Light과 촬영 조명을 담당한다.
Live 조명값은 화면에서만 보관하며, 포인트를 선택하면 저장된 조명값을 불러온다.
Save X/Y + Image는 좌표와 기준 영상을 저장하고, Update Image + Light는 기존 포인트의 영상과 조명만 갱신한다.

별도 Inspection Teaching은 저장된 기준 영상이나 검사 결과 영상을 불러와 ROI·판독 설정을 조정한다.
카메라나 축을 제어하지 않으므로 자동 운전 중에도 사용할 수 있다. 볼트를 선택하면 원본과
이진화 ROI·Bright %를 비교하며 밝기와 최소 비율을 바꿀 수 있다. Data Matrix는 판독 옵션과
임계값 탐색 범위를 조정한다. Data Matrix는 처음부터 최소~최대 임계값을 지정 증가폭으로 탐색한다.
증가폭이 범위를 나누어떨어지지 않아도 최대값은 마지막에 포함하며, 처음 성공하면 탐색을 끝낸다.
각 임계값에서 일반 판독 → 실패 시 다일레이션 판독 → 실패 시 다음 임계값 순서로 진행한다.
점 확장 반경이 1 이상이면 그 임계값의 이진 영상에서 검은 점을 지정 반경만큼 한 번 확장한다
(1픽셀=3×3, 0=확장 끔, 최대 5픽셀). 어느 단계든 처음 성공하면 즉시 종료한다.
기본값은 0~255, 증가폭 5, 확장 반경 1이다. 이전 단일 BinaryThreshold 값은 사용하지 않는다.
검사 화면에는 성공한 시도(전체 실패 시 마지막 시도)의 임계값과 처리 영상을 표시한다.
같은 Threshold와 Dilated 여부를 PCB 결과 DB의 PcbImages.Metadata에 저장한다.
기존 결과처럼 해당 값이 없으면 null을 유지하며, 과거 판독 조건을 추정하지 않는다.
탐색 범위와 원본 영상은 바꾸지 않으며 탐색 도중 STOP/취소를 확인한다.
활성 레시피는 화면과 자동 검사가 같은 객체를 사용하며 편집값을 바로 읽는다.
Save는 현재 검사 설정을 DB에 보관한다. Gantry에서 기록한 좌표와 촬영 조명, 저장된 생산 결과는 덮어쓰지 않는다.

카메라·조명·검사축·Data Matrix 읽기·검사 결과와 NG 이송은 기존 Inspection
프로젝트가 담당한다. 학습·라벨링·모델 관리·자동 학습 이미지 수집 및 Torch 의존성은
제거했다. 실제 카메라와 Virtual 카메라 모두 같은 체커를 사용한다.
